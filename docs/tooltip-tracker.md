# Tooltip Tracker GUI 가이드

학습된 `TooltipDetector` 모델(heatmap 기반, `tooltip-detector.py`와 동일 아키텍처)로 복강경 수술 **동영상**을 실시간 처리하며, 화면 중앙에서 탐지된 수술도구 팁 방향으로 화살표를 그려 내시경 카메라가 이동해야 할 방향을 안내하는 인터랙티브 GUI 도구다.

## 개요

`ttd/tooltip-tracker.py`는 사용자가 선택한 동영상 파일을 프레임 단위로 순차 처리하면서, 매 프레임마다:

1. 모델로 팁 히트맵을 추론하고 피크(팁 후보)를 추출한다.
2. 피크 개수와 방향을 검사해 오탐지 여부를 판정하고, 단일 "화면 중앙 → 팁" 방향 측정값으로 정리한다.
3. 이 측정값을 비대칭 칼만 필터에 입력해 화살표의 길이·방향을 부드럽게 갱신한다.
4. 화면 중앙에서 시작하는 화살표와 보조 시각 지표(원본 팁 마커, 오탐지 경고 도형)를 그린다.

화살표는 **내시경 카메라가 이동해야 할 방향**을 의미하므로, 방향과 길이가 프레임 간에 급격히 바뀌지 않도록 설계되어 있다. 자세한 이유와 로직은 [화살표(카메라 이동 방향) 스무딩 로직](#화살표카메라-이동-방향-스무딩-로직) 절을 참고한다.

## 실행

```bash
bin/tooltip-tracker          # Linux / macOS
bin\tooltip-tracker.bat      # Windows
```

직접 실행:

```bash
uv run python ttd/tooltip-tracker.py
uv run python ttd/tooltip-tracker.py --model-type monai_mini
```

## 인수

| 인수            | 기본값                                    | 설명                                       |
| --------------- | ------------------------------------------ | ------------------------------------------ |
| `--model-type`  | `monai`                                    | 모델 아키텍처 (`monai` / `monai_mini`)     |
| `--model`       | `data/models/<model-type>/best.pt`         | 학습된 모델 가중치 파일 경로               |

동영상 파일은 커맨드라인 인수가 아니라 GUI의 `Open Video...` 버튼으로 선택한다.

### 행 1 — 탐색/재생 컨트롤

| 요소                | 설명                                                              |
| ------------------- | ----------------------------------------------------------------- |
| `Model` 드롭다운    | `monai` / `monai_mini` 전환, 선택한 타입의 `best.pt`를 다시 로드  |
| `Open Video...`     | 동영상 파일 열기 (`.mp4 .avi .mov .mkv .wmv` 등)                  |
| `<-` / `->`         | 이전 / 다음 프레임으로 한 프레임씩 이동 (항상 순차 처리)          |
| `Play` / `Pause`    | 연속 재생 시작 / 정지                                              |
| `N / M` 표시        | 현재 프레임 번호 / 전체 프레임 수                                 |

### 행 2 — 추론·스무딩 파라미터

| 요소                      | 범위          | 기본값 | 설명                                                                 |
| ------------------------- | ------------- | ------ | --------------------------------------------------------------------- |
| `Threshold` 슬라이더      | 0.05 ~ 0.95   | 0.50   | 히트맵 피크 탐지 임계값 (`tooltip-detector.py`와 동일)                |
| `NMS radius` 슬라이더     | 5 ~ 50 px     | 20 px  | 이웃 피크 억제 반경                                                   |
| `Smoothing (grow q)` 슬라이더 | 0.001 ~ 1.0 | 0.05   | 팁을 추적 중일 때 칼만 필터의 process noise. 낮을수록 화살표가 새 방향으로 천천히, 부드럽게 자라난다. **감속(정지) 속도는 이 슬라이더와 무관하게 항상 더 빠르게 고정**되어 있다 (자세한 내용은 아래 참고). |

파라미터를 바꾸면 현재 프레임을 즉시 재추론해 화면을 갱신하지만, 화살표 상태(칼만 필터 값) 자체는 전진하지 않는다 — 새 동영상 프레임을 소비하지 않고 미리보기만 한다.

### 행 3 — 비디오 패널

동영상 프레임은 736 × 480 px에서 추론하고 552 × 360 px(75%)로 축소해 표시한다(작은 화면에서도 창이 화면을 벗어나지 않도록 `tooltip-detector.py`와 동일한 축소 비율을 사용).

| 시각 요소                  | 색상 / 형태                     | 의미                                                                 |
| -------------------------- | -------------------------------- | --------------------------------------------------------------------- |
| 화살표                     | 연두색 `#8CFF3C`                | 이번 프레임에 팁이 1개 이상 탐지됨                                    |
| 화살표                     | 분홍색 `#FF7FCF`                | 이번 프레임에 팁이 0개 탐지됨                                         |
| 파란 원 (⭕)                | `#33AAFF`, 반경 10px, 두께 4px  | 이번 프레임에 탐지된 원본(raw) 팁 후보 위치 (스무딩 이전)             |
| 빨간 다각형 (외곽선만)      | `#EE1111`, 두께 6px             | 팁이 4개 이상 탐지됨 — 변의 수 = 탐지 개수 (5개 초과 시 오각형으로 고정) |
| 빨간 X                     | `#EE1111`, 두께 6px             | 팁이 정확히 2개 탐지되었고 두 팁의 방향 차이가 90° 이상 (2각형이 존재하지 않으므로 X로 대체) |
| 흰 점                       | 중앙 고정                        | 화살표의 시작점(화면 중앙)                                            |

화살표의 색상은 **이번 프레임에 탐지된 원본 팁 개수**만으로 결정된다 — 아래 오탐지 규칙에 의해 측정값이 버려지는 경우(예: 팁 4개, 2개인데 각도 초과)에도 팁이 하나 이상 탐지되었다면 화살표는 계속 연두색이다. 오탐지 여부는 다각형/X 표시와 화살표의 감속 속도로 이미 드러나므로, 색상은 "탐지 자체가 있었는지"만 구분한다.

### 행 4 — 프레임 정보 바

```text
1 tip detected   |   inference: 6.8 ms
raw measurement: (+42.0, -18.0)   smoothed arrow: len=39.7px  angle=-23.3deg
```

| 항목              | 설명                                                            |
| ----------------- | ----------------------------------------------------------------- |
| 첫 줄 앞부분      | 오탐지 판정 사유 (`resolve_measurement()`의 reason 문자열)        |
| `inference`       | 이번 프레임 모델 forward 시간 (ms)                                |
| `raw measurement` | 오탐지 필터링 이후의 측정 벡터. 무효 처리된 경우 `(+0.0, +0.0)`   |
| `smoothed arrow`  | 칼만 필터로 스무딩된 현재 화살표의 길이(px)와 각도(deg)           |

### 행 5 — 탐색 바 (Seekbar)

수평 슬라이더로 동영상 내 임의 프레임으로 이동한다(150 ms 디바운싱). 탐색 바를 조작하면 재생 중이던 경우 자동으로 일시정지된다.

## 조작 방법

### 키보드 단축키

| 키  | 동작                    |
| --- | ----------------------- |
| `←` | 이전 프레임 (재생 중지) |
| `→` | 다음 프레임 (재생 중지) |

### 재생 페이싱 (Play)

`Play`를 누르면 벽시계 시간을 기준으로 동영상의 실제 FPS에 맞춰 재생하려 시도한다. 모델 추론이 프레임 간격보다 오래 걸리면(특히 CPU 환경) **중간 프레임을 건너뛰어** 벽시계 동기화를 우선한다 — 프레임을 역행하거나 재처리하지는 않는다. 동영상 끝에 도달하면 자동으로 일시정지된다.

`<-` `->` 단추 및 화살표 키로 이동할 때는 항상 정확히 한 프레임씩 순차 처리한다(건너뛰지 않음).

## 화살표(카메라 이동 방향) 스무딩 로직

### 왜 칼만 필터로 팁을 직접 추적하지 않는가

수술도구 팁은 일정한 속도나 가속도로 움직이지 않고, 실제 내시경 영상에서는 오히려 랜덤에 가깝게 움직인다. 따라서 팁의 원시 좌표 자체를 칼만 필터로 추적하는 것은 적합하지 않다.

반면 실제로 로봇에 전달되는 신호 — "지금 카메라가 어느 방향으로 움직여야 하는가" — 는 칼만 필터로 스무딩하기에 적합한 문제다. 매 프레임 필터에는 다음 중 하나가 측정값으로 입력된다.

- 팁이 유효하게 탐지됨 → 화면 중앙에서 팁까지의 실제 벡터
- 팁이 탐지되지 않거나 오탐지로 간주됨 → 영벡터 `(0, 0)`

이 방식 덕분에 별도의 "감소 규칙"을 하드코딩하지 않고도, 필터의 일반적인 predict/update 사이클만으로 화살표가 새 방향으로 서서히 수렴하거나 0으로 서서히 감쇠하는 동작이 자연스럽게 나온다.

### 오탐지(false positive) 판정 규칙 — `resolve_measurement()`

| 탐지된 팁 개수 | 판정                                                                 | 화살표 색상 | 추가 시각 지표      |
| -------------- | ---------------------------------------------------------------------- | ----------- | -------------------- |
| 0개            | 무효 (측정값 = 영벡터)                                                  | 분홍        | 없음                  |
| 1개            | 유효 (측정값 = 중앙 → 팁 벡터)                                          | 연두        | 없음                  |
| 2개            | 두 벡터 사이 각도 < 90° → 유효 (두 벡터의 평균을 측정값으로 사용)       | 연두        | 없음                  |
| 2개            | 두 벡터 사이 각도 ≥ 90° → 무효 (모호/오탐지, 측정값 = 영벡터)          | 연두        | **빨간 X**            |
| 3개            | 무효 (측정값 = 영벡터, 오탐지 가능성)                                   | 연두        | 없음                  |
| 4개 이상       | 무효 (측정값 = 영벡터, 오탐지 가능성)                                   | 연두        | **빨간 다각형**(변의 수 = min(개수, 5)) |

주의: 팁이 정확히 3개 탐지된 경우는 무효 처리(화살표가 빠르게 감속)되지만, 다각형 경고 도형은 표시되지 않는다 — 다각형은 "3개 초과"(4개 이상)일 때만 그려진다. 2개가 탐지되었지만 각도가 90° 미만인 경우, 2각형은 존재하지 않으므로 대신 빨간 X로 경고를 표시한다.

### 비대칭 칼만 필터 — `ttd/camera_motion_vector.py`의 `CameraMotionVector`

화살표의 길이·방향 계산 로직은 `ttd/tooltip-tracker.py`가 아니라 별도 모듈 `ttd/camera_motion_vector.py`에 있다. `CameraMotionVector`는 `(dx, dy)` 2차원 random-walk 칼만 필터이며, 이 필터의 process noise(`q`)는 **증가(성장)와 감소(감속)에 서로 다른 값**을 사용한다.

| 상황                                                                                   | 사용하는 q          | 결과                     |
| ---------------------------------------------------------------------------------------- | -------------------- | ------------------------- |
| 새 측정값을 현재 화살표 방향에 투영한 값이 현재 길이보다 **크거나 같음** (같은 방향으로 더 멀리 감지됨) | `q_grow` (슬라이더 조절, 기본 0.05) | 느리고 부드럽게 증가       |
| 그 외 모든 경우 — 탐지 실패, 오탐지로 무효 처리, 또는 **팁이 탐지는 되었지만** 화살표 방향으로의 투영값이 줄어듦(중앙 쪽으로 이동·역방향·측면 이동 포함) | `DECAY_PROCESS_VAR` (고정값 150.0) | 빠르게 0으로 수렴          |

두 번째 규칙이 중요한 이유: 시술자가 로봇(카메라)을 멈추고 싶을 때는 수술도구 팁을 화살표의 반대 방향으로 옮긴다. 이때 팁은 여전히 정상적으로 탐지되고 있으므로, 단순히 "탐지 성공 여부"만으로 증가/감소를 결정하면 이 의도를 놓친다. 따라서 원시 탐지 유효성이 아니라 **현재 화살표 방향으로의 투영값 증감**으로 증가/감소를 판단한다.

감속(`DECAY_PROCESS_VAR = 150.0`)은 `Smoothing (grow q)` 슬라이더와 무관하게 항상 고정된 큰 값이다 — 로봇이 계속 이동해야 할 이유가 없는데도 관성으로 계속 움직이는 것은 안전 문제이므로, "정지"는 슬라이더 설정과 무관하게 항상 "시작"보다 빨라야 하기 때문이다.

### 화살표가 0에서 다시 자라날 때 점프하지 않는 이유

감속 국면(예: 팁을 오래 놓친 경우)에서는 필터의 불확실성(공분산 `P`)이 상대적으로 커진 채로 유지된다. 만약 화살표 길이가 0 근처로 완전히 수렴한 뒤 새 탐지가 들어왔을 때 이 커진 `P`를 그대로 물려받으면, 첫 프레임에 화살표가 목표 방향으로 크게 점프해버리는 문제가 있었다.

이를 막기 위해 화살표 길이가 `FRESH_START_LEN`(2px, 화면에 그려지는 최소 길이와 동일) 미만인 상태에서 유효한 새 탐지가 들어오면, 갱신 전에 `P`를 "지속 추적 중" 상태의 정상 수렴값(steady-state variance)으로 초기화한다. 그 결과 정지 상태에서 다시 자라나는 첫 프레임도, 계속 추적되고 있던 화살표의 통상적인 증가 속도와 동일하게 부드럽게 시작한다 — 이 로직은 매우 처음 켜졌을 때의 첫 탐지에도 동일하게 적용된다.

### 감속 시 정확히 0으로 스냅

감속(random-walk 감쇠)은 수학적으로 0에 점근할 뿐 정확히 0에 도달하지는 않는다(예: 0.03 → 0.01 → 0.001 …). 그대로 두면 `FRESH_START_LEN` 판정이 부동소수점 오차에 취약해지므로, **감속 스텝일 때만** 갱신 후 길이가 `FRESH_START_LEN` 미만이면 상태를 정확히 `(0, 0)`으로 스냅한다. 이 스냅은 반드시 "감속 스텝"일 때만 적용된다 — 0에서 다시 자라나는 성장 스텝의 초반 값(예: 1.11px, 2.21px, …)도 마찬가지로 작기 때문에, 판정 없이 적용하면 화살표가 영원히 0에 갇혀 자라나지 못하는 문제가 생긴다.

## 추론 흐름

```text
동영상 프레임 (BGR, 임의 해상도)
    │
    ▼
cv2.cvtColor → RGB, cv2.resize → 736 × 480
    │
    ▼
_eval_transform()          →  CHW float32 텐서 (정규화)
    │
    ▼
TooltipDetector.forward()  →  (1, 2, H, W) 출력
    │
    ▼
sigmoid(output[:, 1])      →  (H, W) 히트맵 float32 [0, 1]
    │
    ▼
find_peaks(heatmap, threshold, nms_radius)  →  peaks: [(x, y, confidence), ...]
    │
    ▼
resolve_measurement(peaks)  →  (measurement, valid, reason, two_tip_conflict)
    │
    ▼
ArrowState.update(peaks)   →  CameraMotionVector.step(measurement, valid)
    │
    ▼
화살표 벡터 (dx, dy) 갱신  →  화면 렌더링 (화살표 + 마커 + 경고 도형)
```

### 클래스 구조

`CameraMotionVector`는 `ttd/camera_motion_vector.py`에, 나머지는 모두 `ttd/tooltip-tracker.py`에 있다.


## 주의 사항

- 모델 파일이 없거나 로드에 실패하면 경고 메시지를 출력하고 탐지 없이(피크 0개) 실행된다. 화살표는 항상 분홍색으로 표시되고 서서히 0으로 수렴한다.
- CPU 환경에서는 모델 추론이 동영상 프레임 간격보다 오래 걸릴 수 있다. 이 경우 `Play` 재생은 벽시계 동기화를 위해 프레임을 건너뛴다 — 정확한 프레임 단위 분석이 필요하면 `<-` `->`로 한 프레임씩 순차 이동한다.
- 화살표는 로봇 제어 신호가 아니라 **시각화**이며, 실제 로봇 구동 로직과는 별개다.
- 누적 평가 통계는 제공하지 않는다(GT 어노테이션이 없는 동영상이 입력이므로). 정량 평가가 필요하면 `bin/eval-model` 또는 `bin/tooltip-detector`(dataset 모드)를 사용한다.
