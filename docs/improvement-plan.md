# 목표 성능(`tip` AP@0.5 ≥ 0.90) 달성을 위한 개선 방안

- **작성일:** 2026-10-23
- **목표 지표:** `tip` AP@0.5 ≥ 0.90 (단일 클래스, `tool` AP는 평균에 넣지 않는다)
- **기준 데이터셋:** `cholec80` (영상 단위 분할, 시간적 누수 없음)
- **근거 자료:** [final-report.md](final-report.md), [baseline-report.md](baseline-report.md),
  [parameter-optimization.md](parameter-optimization.md), [dataset-guide.md](dataset-guide.md)

이 문서는 새로운 실험을 수행하지 않고, 이미 수행된 열두 회차(히트맵 8개 조합 + 베이스라인
5종)의 기록만으로 **목표까지의 격차가 어디에서 오는지 분해하고 개선 순서를 정한 것**이다.
수치는 모두 위 보고서에서 인용했으며 새로 계산한 것은 §1.2의 IoU 기하 관계뿐이다.

## 0. 작성 시점에 확정된 전제

사용자 확인을 거쳐 아래를 전제로 한다.

| 항목                  | 결정                          | 이 문서에 미치는 영향                                                                  |
| --------------------- | ----------------------------- | -------------------------------------------------------------------------------------- |
| 목표 지표             | `tip` AP@0.5 단독 ≥ 0.90      | `tool` AP(0.835〜0.838)는 목표에서 제외된다. 격차 전부가 `tip`에 집중된다              |
| 팁 좌표 허용 오차     | **미정**                      | 32 px 팁 상자를 고정값으로 두지 않고, 상자 크기별 AP를 병기하는 방식으로 다룬다 (§2.1) |
| 사람 검수 테스트 세트 | 1,000〜2,000 프레임 구축 가능 | §3의 2순위 항목이 실행 가능 경로가 된다                                                |

## 1. 격차 분해

### 1.1 출발점

`cholec80` test의 `tip` AP@0.5는 다음과 같다 ([baseline-report.md](baseline-report.md) 표 6).

| 모델                         | `tip` AP@0.5 | `tip` AP@0.5:0.95 | 목표까지 |
| ---------------------------- | -----------: | ----------------: | -------: |
| YOLOv8s(참조, COCO 사전학습) |    **0.671** |             0.413 |   +0.229 |
| YOLOv8s(재구현)              |        0.666 |             0.408 |   +0.234 |
| YOLO26(참조)                 |        0.643 |             0.425 |   +0.257 |
| YOLO26(재구현)               |        0.632 |             0.415 |   +0.268 |
| CLAD-Net(재구현)             |        0.577 |             0.303 |   +0.323 |

참고로 `erop`의 최고값은 0.828(YOLOv8s 참조)로 목표에 훨씬 가깝지만, `erop`은 프레임 단위
분할이라 같은 영상의 인접 프레임이 train과 test에 함께 들어간다. 이 수치는 일반화 성능이
아니므로 목표 달성의 근거로 쓸 수 없다. 기준은 `cholec80`이다.

### 1.2 `tip` AP@0.5가 실제로 요구하는 것

`tip` 클래스는 팁 좌표를 중심으로 한 32 × 32 px 정사각 상자다. 같은 크기 정사각형 두 개를
중심 오차 `(dx, dy)`만큼 어긋나게 놓았을 때의 IoU는 다음과 같다.

```text
IoU = (s - dx)(s - dy) / (2s² - (s - dx)(s - dy))
```

IoU = 0.5를 풀면 `(s - dx)(s - dy) = (2/3)s²`이다. 즉 **`tip` AP@0.5는 "팁 좌표를 중심 오차
0.33·s(축 방향) 또는 0.26·s(대각 방향) 이내로 맞혔는가"를 묻는 지표**이며, 상자 크기 `s`가
허용 오차를 직접 결정한다.

|      팁 상자 `s` | 축 방향 허용 오차 | 대각 방향 허용 반경 | 대응하는 Hit@N   |
| ---------------: | ----------------: | ------------------: | ---------------- |
|            24 px |            8.0 px |              6.2 px | Hit@6〜8 px      |
| **32 px (현행)** |       **10.7 px** |          **8.3 px** | **Hit@8〜11 px** |
|            48 px |           16.0 px |             12.5 px | Hit@13〜16 px    |
|            64 px |           21.3 px |             16.6 px | Hit@17〜21 px    |
|            96 px |           32.0 px |             24.9 px | Hit@25〜32 px    |

따라서 현행 32 px 설정에서 `tip` AP@0.5 ≥ 0.90은 **Hit@10 px ≳ 90 %** 를 요구한다. 현재
최고값은 62.90 %다.

### 1.3 상자를 키워도 목표에 닿지 못한다

허용 오차가 미정이므로 "상자를 키워 허용 오차를 넓히면 되지 않는가"가 자연스러운 질문이다.
답은 **아니오**이며, 근거는 Hit 곡선의 포화에 있다 ([baseline-report.md](baseline-report.md) 표 7,
`cholec80`).

| 모델                  | Hit@10 px | Hit@20 px |   Hit@50 px | 탐지 실패율 |
| --------------------- | --------: | --------: | ----------: | ----------: |
| YOLOv8s(참조)         |   62.90 % |   69.01 % | **75.80 %** |      6.34 % |
| YOLOv8s(재구현)       |   59.87 % |   65.48 % |     71.78 % |      8.82 % |
| YOLO26(참조)          |   61.57 % |   67.02 % |     73.31 % |      7.45 % |
| CLAD-Net              |   56.65 % |   63.12 % |     69.96 % |      9.56 % |
| 히트맵 `gaussian-tip` |   59.55 % |   67.45 % |     74.72 % |      7.48 % |
| 히트맵 `gradient-seg` |   30.04 % |   55.58 % |     76.12 % |      2.90 % |

**거리 허용치를 10 px에서 50 px로 다섯 배 넓혀도 13 %p만 오르고 75.8 %에서 멈춘다.** 상자를
96 px까지 키워도 얻는 것은 72 % 남짓이고, 90 %를 넘기려면 상자 변 길이가 150 px를 넘어야
하는데 그것은 더 이상 "팁 탐지"가 아니다.

남은 24 %는 위치를 틀린 것이 아니라 **후보가 아예 없는 팁**이다. 이것이 이 문서의 핵심
판단이다.

### 1.4 재현율이 AP의 절대 상한을 만든다

AP는 PR 곡선 아래 면적이므로 **최대 재현율을 넘을 수 없다.** AP 곡선용으로 신뢰도 문턱을
`conf=0.001`까지 연 상태에서의 `tip` 재현율은 YOLOv8s 0.910, YOLO26 0.893이다
([baseline-report.md](baseline-report.md) §3.1).

```text
tip AP@0.5  ≤  max recall@IoU 0.5  =  0.910   (YOLOv8s, cholec80)
```

목표 0.90은 이 상한의 98.9 %다. 즉 **지금의 후보 생성 능력으로는, 정밀도가 완벽한 이상적인
PR 곡선을 그려도 목표에 간신히 닿거나 닿지 못한다.** 목표 달성의 필요조건은 후처리나 랭킹
개선이 아니라 **최대 재현율을 0.95 수준까지 끌어올리는 것**이다.

### 1.5 재현율을 막는 것은 인스턴스 분리다

놓치는 팁의 정체는 세 보고서가 독립적으로 같은 곳을 가리킨다.

- **큰 오차의 정체가 과소 탐지다.** 200 px 이상 오차의 **82.1〜88.5 %** 는 한 프레임의 도구
  하나를 통째로 놓쳐 그 GT가 다른 도구의 예측에 매칭된 경우다
  ([baseline-report.md](baseline-report.md) 표 16).
- **도구 수가 늘면 무너진다.** 50 px 상한 헝가리안 성공률이 `cholec80`에서 도구 1개 76.4〜77.0 %,
  도구 3개 61.5〜62.6 %다. 히트맵 계열의 낙폭(14.3〜18.8 %p)과 탐지기 계열의 낙폭
  (14.4〜15.0 %p)이 같은 범위다 ([final-report.md](final-report.md) 표 31, 표 32).
- **처방이 모두 듣지 않았다.** NMS를 없앤 end-to-end 헤드(YOLO26)에서도 공유 비율은 87.2 %로
  그대로였고, `tool` 감독을 뺀 `tiponly` 여섯 회차에서도 82.2〜87.7 %로 같았으며, COCO
  사전학습 회차에서도 85 %대로 남았다.
- **후처리로 닿는 크기가 아니다.** threshold × NMS 격자 탐색 전체의 효과는 F1@50 +0.003〜0.027,
  watershed는 +0.001〜0.002였다 ([parameter-optimization.md](parameter-optimization.md),
  [final-report.md](final-report.md) §11.1).

아키텍처 다섯 종, 헤드 설계 세 종, 후처리 전수 탐색이 모두 같은 벽에서 멈췄다. **이것은
특정 모델의 약점이 아니라 "한 프레임에 비슷하게 생긴 도구가 둘 이상 있을 때 그중 하나만 높은
점수를 받는다"는 과제 정식화의 문제다.**

### 1.6 그리고 기준값 자체가 검증되지 않았다

두 데이터셋의 마스크·팁·바운딩 박스는 모두 **MONAI 사전학습 분할 모델 추론과 contour 기하
휴리스틱으로 생성된 반자동 라벨이며, 사람의 검증을 거치지 않았다**
([final-report.md](final-report.md) §2.3, [dataset-guide.md](dataset-guide.md)). 팁 선택
규칙은 "무게중심에서 가장 먼 두 극점 중 영상 중심에 더 가까운 점"이고, 보고서는 이 휴리스틱이
도구의 반대쪽 끝을 고르는 실패와 마스크 노이즈를 가짜 인스턴스로 잡는 과분할이 존재함을
명시한다.

문제의 심각성은 **요구 정밀도와 라벨 불확실성이 같은 자릿수**라는 데 있다. 32 px 상자의
`tip` AP@0.5는 8〜11 px 정확도를 요구하는데, 보고서 스스로 "`gaussian-tip`의 중앙값 오차
3〜4 px는 어노테이션 자체의 불확실성과 같은 자릿수일 가능성이 있다"고 적었다
([final-report.md](final-report.md) §8.1). GT가 10 px 이상 틀린 팁이 전체의 `x` %라면
`tip` AP@0.5의 상한은 그만큼 깎이는데, **지금은 그 `x`가 얼마인지 모른다.**

`cholec80` train에는 도구 4개 이상으로 레이블링된 프레임이 5.6 % 남아 있고(평가에서만 제외됐다),
도구 5개 이상 프레임의 어노테이션 10,764개 중 1,701개(15.8 %)는 bbox 면적이 100 px² 미만인
조각이다 ([final-report.md](final-report.md) §2.7). 모델은 이 가짜 인스턴스를 학습한 상태다.

## 2. 개선 방안

### 2.1 측정을 먼저 고정한다

모델을 바꾸지 않고도 `tip` AP를 유의미하게 움직이는 항목이며, 비용이 거의 없고 이후 모든
실험의 해석 기준이 된다.

**(a) 팁 상자 크기별 AP 병기.** 허용 오차가 미정이므로 단일 값을 고르지 말고 24 / 32 / 48 /
64 px 네 크기로 AP를 함께 보고한다. §1.2의 환산표가 각 크기의 의미를 말해 주므로, 응용
요구사항이 확정되는 시점에 해당 행을 고르면 된다. 기존 체크포인트의 예측 좌표만 있으면
재학습 없이 계산할 수 있다. **다만 §1.3에서 보았듯 상자 확대만으로는 목표에 닿지 않는다.**
이 항목의 목적은 AP를 올리는 것이 아니라 **요구사항과 지표를 일치시키는 것**이다.

**(b) 가짜 인스턴스 프레임의 AP 평가 제외.** 히트맵 쪽 4.0판은 도구 4개 이상 프레임
(`cholec80` test의 4.2 %)을 평가에서 제외했으나, 베이스라인 AP는 제외 없이 계산됐다
([final-report.md](final-report.md) 표 31 주석). 존재하지 않는 도구의 팁을 FN으로 세는 한
AP는 구조적으로 깎인다. 같은 규칙(`--max-tools 3`)을 AP 계산에도 적용해야 두 계열을 같은
기준으로 견줄 수 있다.

**(c) `conf` 임계값 스윕.** 다섯 회차 모두 `conf=0.25` 고정이다
([baseline-report.md](baseline-report.md) §6.2). AP 자체는 전 구간 곡선이므로 영향이 없지만,
운용 지점 지표와 AP의 괴리를 파악하는 데 필요하다.

**(d) 히트맵 모델을 AP 표에 올린다.** 현재 "세그멘테이션 기반은 상자를 내놓지 않으므로 AP를
정의할 수 없다"고 되어 있다. 그러나 히트맵 피크는 좌표와 신뢰도를 모두 갖고 있으므로 같은
크기의 상자로 변환하면 `tip` AP를 그대로 계산할 수 있다. `gaussian-tip`은 헝가리안 정밀도
0.772로 일곱 회차 중 최고였고([baseline-report.md](baseline-report.md) 표 8) Hit@20 px·
Hit@50 px에서도 탐지기를 앞선다. **측정만으로 현재 최고 `tip` AP가 바뀔 가능성이 있다.**

### 2.2 기준값의 신뢰도를 확보한다

**(e) 사람 검수 테스트 세트 (1,000〜2,000 프레임).** 전체에서 가장 중요한 단일 항목이다.

- `cholec80` test에서 도구 수별·영상별로 층화 추출한다. 도구 3개 구간과 `video50`을 과표집한다.
- `tooltip-annotator` GUI로 팁 좌표와 도구 상자를 검수한다. 새 도구를 만들 필요가 없다.
- **같은 체크포인트를 원본 GT와 검수 GT 양쪽으로 채점한다.** 두 `tip` AP의 차이가 곧 라벨
  노이즈가 깎고 있던 몫이며, 진짜 천장이 어디인지를 처음으로 알게 된다.
- 부수적으로 휴리스틱 실패 유형별 비율(반대쪽 끝 선택 / 과분할 / 누락)을 집계하면 §2.3의
  정제 규칙을 데이터로 설계할 수 있다.

이 측정 없이는 앞으로의 모든 개선이 **모델 개선인지 라벨 노이즈와의 싸움인지 구분되지 않는다.**
현재 목표 격차가 0.229인데, 라벨 노이즈가 그중 0.05를 차지하는지 0.15를 차지하는지에 따라
이후 자원 배분이 완전히 달라진다.

**(f) train 라벨 정제 후 재학습.** 평가 제외는 학습 신호를 교정하지 않는다. 도구 4개 이상
프레임(train의 5.6 %)과 bbox 면적 100 px² 미만 조각을 필터링한 뒤 재학습한다. (e)에서 얻은
실패 유형 통계가 있으면 면적 기준 외의 규칙도 설계할 수 있다.

**(g) `video50` 개별 조사.** 네 조합 모두에서 평균 거리 93.5〜100.5 px로 바로 위 영상의
1.5〜1.8배다([final-report.md](final-report.md) §6.6). 모델과 타겟 방식이 바뀌어도 순위가
유지된다는 것은 원인이 데이터 속성이라는 뜻이고, 휴리스틱 팁 선택 실패가 1순위 용의자다.
영상 한 편이 test의 2.5 %이므로 AP에 실제로 영향을 준다.

### 2.3 인스턴스 분리를 정면으로 겨냥한다

§1.5에서 보았듯 이것이 재현율 상한을 만드는 원인이며, 기존 다섯 회차가 모두 실패한 지점이다.

**(h) 2단계 top-down 팁 회귀.** 모델 쪽 1순위로 추천한다. 세 가지 관찰이 맞물린다.

1. `tool` AP@0.5가 0.835〜0.838로 **도구 찾기는 거의 풀린 문제**다.
2. 단독 매칭된 팁의 오차는 중앙값 3〜4 px로, **인스턴스가 분리되기만 하면 위치는 이미 정확하다**
   ([final-report.md](final-report.md) §6.7).
3. 병목은 오직 "둘 이상의 비슷한 도구 중 하나만 높은 점수를 받는" 문제다.

도구 상자로 crop한 뒤 그 안에서 팁을 회귀하면 **인스턴스당 팁 하나가 구조적으로 보장되어
공유 피크 문제가 정의상 사라진다.** 동시에 crop 해상도가 올라가 서브픽셀 정밀도도 함께 얻는다.
자세 추정의 top-down 방식과 같은 구도이며, **지금까지의 일곱 회차가 모두 one-stage였다는
점에서 가장 크게 비어 있는 설계 공간이다.** 1단계는 기존 YOLOv8s 체크포인트를 그대로 쓸 수
있으므로 2단계 회귀기만 새로 학습하면 된다.

**(i) 시간 정보의 도입.** 입력이 동영상인데 일곱 회차 모두 프레임을 독립적으로 처리한다.
보고서는 과소 탐지가 "기구가 화면에 막 들어오거나 나가는 장면, 일부만 보이는 장면"에 몰린다고
관찰했는데([baseline-report.md](baseline-report.md) §6.1), **그것은 바로 직전 프레임을 보면
풀리는 장면이기도 하다.** 프레임 3〜5장 스택 입력, 또는 트랙 기반 후처리로 접근할 수 있고,
후자는 `tooltip-tracker`에 이미 스무딩 구현이 있다. 평가는 `cholec80`에서만 해야 한다
(`erop`은 누수 때문에 시간 정보의 이득을 측정할 수 없다).

### 2.4 소형 객체 표현과 학습 설정

**(j) 입력 캔버스와 P2 헤드.** 640 × 640 letterbox는 34.8 %가 패딩이고, 32 px 팁 상자는
stride 8의 P3 격자에서 4 px짜리다. 800 × 512로 바꾸면 같은 연산량에서 물체가 23 % 커지고
objectness 기울기가 1.53배가 된다([baseline-report.md](baseline-report.md) §7-4). stride 4의
P2 헤드를 더하면 격자 해상도가 두 배가 된다. 소형 객체 과제에서 효과가 가장 잘 알려진 조합이고
구현 비용이 낮다.

**(k) 탐지기는 train 프레임의 20 %만 쓰고 있다.** `--frame-stride 5` 때문에 `cholec80`의 train
71,032 프레임 중 14,207장만 학습했다([baseline-report.md](baseline-report.md) §2.5). 인접
프레임이 중복이라는 것은 맞지만, 이미 3 fps로 샘플링된 데이터에서 다시 1/5을 버리는 것은
과하다. stride 2로 한 회차 돌리는 것은 코드 변경 없이 가능한 가장 싼 실험이며, 150 에포크라는
예산도 함께 재조정해야 한다.

**(l) 사전학습 가중치 불일치 확인.** README의 "전이 학습" 절은 `temp/monai.pt`를 초기값으로
사용한다고 기술하지만, [scripts/train-model.py](../scripts/train-model.py)에서 가중치를 불러오는
경로는 재개용 `last.pt` 분기뿐이고([train-model.py:307-311](../scripts/train-model.py#L307-L311)),
저장소 전체에 `temp/monai.pt`를 여는 코드가 없다. **히트맵 8개 조합은 실제로는 스크래치
학습이었을 가능성이 높다.** 문서 오류인지 미적용인지 확인이 필요하며, 후자라면 베이스라인에서
사전학습이 탐지 실패율을 2.3〜2.5 %p 낮춘 전례가 있으므로 전 조합 재학습의 근거가 된다.

**(m) 손실 함수와 서브픽셀 offset.** 현재 히트맵 손실은 `MSE(sigmoid(pred[:, 1]), target)`로,
배경 픽셀이 압도적인 상황에서 팁 근처의 기울기가 희석된다. CenterNet 계열의 focal 가중 히트맵
손실이 표준적인 교체 대상이다. 또한 8개 조합 중 5개에서 4.5〜5.7 px의 계통 편차가 관측되었고
그 상수만 빼도 중앙값이 7.28 → 3.61 px로 회복되는데([final-report.md](final-report.md) §6.3.1),
**이것은 사후 보정이 아니라 offset 헤드로 구조적으로 제거해야 할 양자화 오차다.** 8〜11 px을
다투는 과제에서 5 px 편차는 그냥 둘 수 없다.

## 4. 달성 가능성에 대한 판단

**현재의 미검증 GT를 기준으로 삼는 한 `cholec80`에서 `tip` AP@0.5 0.90은 달성하기 어렵다고
본다.** 근거는 §1.4의 상한이다. `conf=0.001`까지 연 최대 재현율이 0.910이므로, 정밀도가
완벽한 이상적 PR 곡선을 그려도 목표에 간신히 닿는다. 그리고 그 재현율을 막는 과소 탐지는
다섯 아키텍처·세 가지 헤드 설계·후처리 전수 탐색에서 모두 같은 크기로 남았다.

반대로 다음 두 조건이 충족되면 현실적인 목표가 된다.

1. **(e)의 검수 세트에서 라벨 노이즈가 `tip` AP를 0.05 이상 깎고 있었음이 확인될 것.**
   요구 정밀도 8〜11 px과 라벨 불확실성이 같은 자릿수라는 점에서 가능성이 작지 않다.
2. **(h) 또는 (i)로 과소 탐지를 절반으로 줄여 최대 재현율을 0.95 수준으로 올릴 것.**

이 두 몫의 크기를 모르는 상태에서 하이퍼파라미터와 아키텍처를 더 바꾸는 것은, 지금까지의
다섯 회차가 보여 주듯 `tip` AP를 0.01 단위로만 움직일 것이다(아키텍처 사이의 격차
0.054〜0.070, 사전학습 + 증강 + 구현체 묶음의 효과 0.003〜0.010).

**덧붙여, 허용 오차가 확정되면 목표의 난이도 자체가 달라진다.** 응용이 요구하는 정확도가
20 px이라면 64 px 상자 기준으로 목표를 다시 읽어야 하고, 그 경우 격차는 §1.3의 Hit@20 px
기준으로 재계산된다. §2.1(a)의 상자 크기별 병기가 이 판단의 근거를 미리 쌓아 둔다.

## 5. 이 문서의 한계

- **새 실험을 수행하지 않았다.** 모든 수치는 기존 보고서 인용이며, §1.2의 IoU 환산만 새로
  계산했다. 개선 항목의 기대 효과는 정량 예측이 아니라 근거에 기반한 판단이다.
- **`tip` AP의 절대 상한 0.910은 YOLOv8s 재구현 회차의 값이다.** 다른 회차·다른 설정에서
  재현율이 더 높을 수 있으며, §2.1(d)에서 히트맵 모델의 AP를 산출하면 상한이 달라질 수 있다.
- **(l)의 사전학습 불일치는 코드 검토에 근거한 추정이다.** 실제로 전이 학습이 적용되지 않았는지
  확인이 필요하다.
- **2단계 구조(h)의 기대 효과는 설계 논리에 근거하며 실측된 것이 아니다.** 1단계 `tool` 상자의
  재현율이 곧 상한이 되므로, 도구 자체를 놓치는 프레임에서는 같은 실패가 남는다.
