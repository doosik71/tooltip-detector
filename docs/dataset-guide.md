# 데이터셋 가이드

수술도구 분할 및 팁(tip) 탐지를 위한 학습 데이터셋의 구조와 포맷을 설명한다. 이 프로젝트는 `data/dataset/<dataset-name>/` 아래에 여러 데이터셋을 나란히 둘 수 있으며, 학습·평가·GUI 스크립트는 `--dataset` 인자(필수)로 어떤 데이터셋을 쓸지 선택한다. `data/dataset/`은 프로젝트 외부에서 구축되는 read-only 마운트다.

공통 포맷은 아래 "공통 구조"에서 설명하고, 데이터셋마다 다른 세부 통계(세션 구성, 프레임 수, 도구 수 분포 등)와 **스플릿 분할 규칙**은 데이터셋별 섹션에 정리한다. 두 데이터셋의 분할 규칙은 서로 다르다 — `erop`은 프레임 단위, `cholec80`은 영상 단위다(아래 [분할 단위](#분할-단위-split-unit) 참고).

## 공통 구조

### 디렉터리 구조

```text
data/dataset/<dataset-name>/
├── annotation/
│   ├── train/
│   ├── val/
│   └── test/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
├── segmentation/
│   ├── train/
│   ├── val/
│   └── test/
└── split-manifest.json     # (선택) 분할 규칙과 모달리티별 파일 수 기록
```

`annotation`, `images`, `segmentation`은 동일한 베이스명(예: `{stem}.json` / `{stem}.png` / `{stem}.png`)으로 1:1 대응한다. `SurgicalToolDataset`(`ttd/dataset.py`)이 이 구조를 그대로 읽으므로, `root` 인자에 `data/dataset/<dataset-name>/`을 넘기면 어떤 데이터셋이든 동일한 코드로 로드된다. 파일 명명 규칙(스템 구성)과 정확한 해상도·프레임 수는 데이터셋마다 다르므로 아래 데이터셋별 섹션을 참고한다.

`split-manifest.json`은 데이터셋을 생성한 스크립트가 남기는 기록으로, 분할 규칙과 모달리티별 파일 수를 담는다. 학습·평가 코드는 이 파일을 읽지 않으며(디렉터리 구조만 보고 로드한다), 어떤 규칙으로 분할됐는지 사후에 확인하는 용도다. 현재 `cholec80`에만 존재한다.

```json
{
  "source": "data/dataset/cholec80",
  "split_rule": "video01-32 train, video33-40 val, video41-80 test",
  "counts": {
    "images":       { "train": 71032, "val": 15312, "test": 98234 },
    "segmentation": { "train": 71032, "val": 15312, "test": 98234 },
    "annotation":   { "train": 71032, "val": 15312, "test": 98234 }
  }
}
```

### 분할 단위 (split unit)

프레임을 train/val/test로 나누는 단위는 두 가지이며, 데이터셋 생성 시 `scripts/generate_dataset.py`의 `--split-unit`으로 정한다.

| 분할 단위             | 배정 방식                                                                     | 시간적 누수 | 현재 사용 데이터셋            |
| --------------------- | ----------------------------------------------------------------------------- | ----------- | ----------------------------- |
| `frame` (기본값)      | 영상마다 독립적으로 그 영상의 프레임을 세 스플릿에 무작위 배분 — 모든 영상이 세 스플릿에 등장 | **있음**    | `erop`                        |
| `video`               | 영상 단위로 하나의 스플릿에만 배정 — 어떤 영상도 두 스플릿에 걸치지 않음      | 없음        | `cholec80`                    |

`frame`은 모든 영상이 세 스플릿에 고르게 기여하므로 스플릿 간 시각적 도메인이 균형을 이루지만, **같은 영상의 시간적으로 인접한 프레임이 train과 test에 동시에 존재한다**. 샘플링 간격이 1초 안팎이면 인접 프레임의 장면이 거의 동일하므로, 이렇게 측정한 test 성능은 미지의 새 영상에 대한 일반화 성능보다 낙관적으로 나온다(temporal leakage).

`video`는 이 누수가 구조적으로 발생하지 않아 test 성능이 곧 미지의 새 영상에 대한 성능이다. 대신 (i) 스플릿마다 시각적 도메인이 달라져 난이도가 올라가고, (ii) 영상 길이 편차가 그대로 프레임 수 편차로 나타나 비율이 정확히 맞지 않는다. 또한 난수를 전혀 쓰지 않으므로(정렬된 파일 목록과 비율만으로 결정) `--seed`나 파일 경로에 무관하게 재현된다.

두 분할 단위가 실제 성능 수치에 만드는 차이는 `cholec80`에서 같은 프레임 집합·같은 학습 설정으로 직접 측정되어 있다 — [final-report.md](final-report.md) §11.3 참고.

### images

- **포맷**: PNG, RGB (3채널)
- **해상도**: 736 × 480 px (두 데이터셋 모두 동일)
- 복강경(laparoscope) 수술 영상 프레임이다. 원본 영상의 종횡비를 유지한 letterbox 방식으로
  736 × 480 캔버스에 맞춰져 있어, 16:9 원본의 경우 상·하단에 각각 약 33 px의 검은 패딩이 생긴다.

### segmentation

- **포맷**: PNG, 그레이스케일 (L 모드)
- **픽셀값**: `0` = 배경, `255` = 수술도구 영역
- images와 1:1 대응. 수술도구가 없는 프레임의 마스크는 전부 0이다.

### annotation

- **포맷**: JSON
- **필드 구조** (데이터셋에 관계없이 동일한 스키마로 가정 — 어느 원본 영상이든 같은 어노테이션 도구로 라벨링된다는 전제):

```json
{
  "image":  "doctor_250620_084707_00000030.png",
  "width":  736,
  "height": 480,
  "annotations": [
    {
      "bbox": { "x": 63, "y": 136, "width": 92, "height": 51 },
      "tip":  { "x": 154, "y": 176 }
    },
    {
      "bbox": { "x": 186, "y": 225, "width": 465, "height": 198 },
      "tip":  { "x": 186, "y": 240 }
    }
  ]
}
```

| 필드                 | 설명                                                                         |
| -------------------- | ---------------------------------------------------------------------------- |
| `image`              | 대응하는 이미지 파일명                                                       |
| `width`, `height`    | 이미지 해상도                                                                |
| `annotations`        | 프레임 내 수술도구 목록 (없으면 빈 배열 `[]`)                                |
| `annotations[].bbox` | 수술도구의 경계 상자 — 좌상단 좌표 `(x, y)` 와 `width`, `height` (픽셀 단위) |
| `annotations[].tip`  | 수술도구 끝부분(팁)의 픽셀 좌표 `(x, y)`                                     |

좌표계: 좌상단이 원점 `(0, 0)`, x축이 오른쪽, y축이 아래쪽.

### annotation ↔ segmentation 대응

annotation의 `annotations` 배열이 비어있지 않은 프레임에는 거의 항상 segmentation 마스크가 존재한다. 라벨링 오류나 경계 케이스로 인해 소수의 프레임에서 둘 사이 불일치가 발생할 수 있다 (erop 기준 실측치는 아래 참고).

## erop 데이터셋 (`--dataset erop`)

내부에서 구축한 복강경 수술 데이터셋 (비공개).

### 개요

5개의 복강경 수술 세션에서 추출한 총 **180,706 프레임** (736 × 480 px), 도구 팁 어노테이션 **252,977개**.

| 스플릿 | 프레임 수 | 비율 | 팁 수   |
| ------ | --------: | ---: | ------: |
| train  |   108,424 | 60 % | 151,329 |
| val    |    36,140 | 20 % |  50,930 |
| test   |    36,142 | 20 % |  50,718 |

각 프레임마다 RGB 이미지, 이진 분할 마스크, 도구 팁 좌표 어노테이션이 제공된다. 프레임은 원본 영상에서 약 10프레임(초당 약 3프레임) 간격으로 샘플링됐다.

### 분할: 프레임 단위 (`--split-unit frame`, 60:20:20)

분할은 **세션마다 독립적으로**(각 세션이 세 스플릿 모두에 60:20:20으로 기여) 수행되며, 세션 내에서는 시간 순서가 아니라 **프레임 단위 무작위 셔플**로 나뉜다. 실제 파일명을 보면 한 세션의 인접 프레임 번호가 train·val·test에 뒤섞여 나타난다.

```text
doctor_250620_084707 세션의 프레임 번호
  train : 30  40  50  60  80  90 100 120 130 140 150 ...
  val   : 10  20  70 110 190 300 310 450 530 540 560 ...
  test  : 260 280 330 360 400 430 460 470 550 570 660 ...
```

따라서 **같은 세션의 시간적으로 인접한 프레임이 train과 test에 동시에 존재**한다. 10프레임(약 0.3초) 간격 샘플링에서 인접 프레임은 장면이 거의 동일하므로, 이 분할로 측정한 test 성능은 미지의 새 영상에 대한 일반화 성능보다 낙관적으로 나온다(시간적 누수, temporal leakage).

`erop`은 세션이 5개뿐이어서 영상 단위 분할로 바꾸면 test가 1개 세션에 의존하게 되고, 세션 하나의 특성이 전체 지표를 지배한다. 따라서 `erop`은 프레임 단위 분할을 유지하며, **`erop`의 test 성능은 일반화 성능이 아니다.** 영상 단위 분할로 재구축된 것은 영상이 80편인 `cholec80`뿐이다.

### 파일 명명 규칙

모든 파일은 동일한 베이스명을 공유한다.

```text
{세션ID}_{프레임번호:08d}.{ext}
```

| 구성 요소    | 설명                                                | 예시                   |
| ------------ | --------------------------------------------------- | ---------------------- |
| `세션ID`     | `doctor_YYMMDD_HHMMSS` 형식의 촬영 세션 식별자      | `doctor_250620_084707` |
| `프레임번호` | 원본 영상에서의 0-기준 프레임 인덱스 (8자리 0-패딩) | `00000030`             |

예시: `doctor_250620_084707_00000030.json / .png`

### 촬영 세션

데이터는 5개의 독립적인 수술 영상 세션에서 추출됐다. 각 세션은 세 스플릿 모두에 등장한다.

| 세션 ID                | train  | val    | test   | test 팁 수 |
| ---------------------- | ------ | ------ | ------ | ---------: |
| `doctor_250620_084707` | 14,406 | 4,802  | 4,802  |      6,735 |
| `doctor_250620_131843` | 16,249 | 5,416  | 5,416  |      4,287 |
| `doctor_250702_084355` | 11,165 | 3,721  | 3,722  |      5,483 |
| `doctor_250702_101536` | 46,193 | 15,397 | 15,398 |     25,137 |
| `doctor_250723_094100` | 20,411 | 6,804  | 6,804  |      9,076 |

세션 `doctor_250702_101536`이 전체 프레임의 약 43 %, test 팁의 약 50 %를 차지하는 지배적 세션이다.

### 프레임당 수술도구 수 분포 (train)

| 도구 수       | 프레임 수 | 비율   |
| ------------- | --------: | -----: |
| 0 (도구 없음) |    23,159 | 21.4 % |
| 1             |    37,121 | 34.2 % |
| 2             |    34,237 | 31.6 % |
| 3             |    10,768 |  9.9 % |
| 4             |     2,502 |  2.3 % |
| 5+            |       637 |  0.6 % |

약 79 %의 프레임에 수술도구가 하나 이상 등장하며, 도구 보유 프레임당 평균 도구 수는 약 1.78개다. 도구가 없는 프레임(21.4 %)은 타겟 히트맵 전체가 0이 되어, "도구가 없을 때 피크를 만들지 않는" 능력을 학습시키는 음성(negative) 샘플로 기능한다.

### annotation ↔ segmentation 불일치율

약 1 % 미만의 프레임에서 annotation과 segmentation 간 불일치가 관찰됐다(라벨링 오류 또는 경계 케이스). 또한 소수의 프레임에서 PNG 파일이 손상되어 있어, `SurgicalToolDataset`은 로드에 실패한 샘플을 다른 샘플로 대체하고 경고만 출력한다.

## cholec80 데이터셋 (`--dataset cholec80`)

공개된 Cholec80 복강경 담낭절제술 영상 데이터셋(80편)을 이 프로젝트의 공통 포맷(위 "공통 구조")으로 변환한 것이다. 구축이 완료되어 **학습·평가에 사용할 수 있다**.

> **2026-08-21 재구축.** 이 데이터셋은 원래 `erop`과 같은 **프레임 단위** 분할(60:20:20)로 구축됐으나, 시간적 누수 없는 일반화 성능을 측정하기 위해 **영상 단위** 분할로 재구축되었다. 프레임 이미지·마스크·어노테이션 자체는 그대로이고 스플릿 배정만 바뀌었다. 구 분할로 학습·평가한 체크포인트와 결과는 `data/models/cholec80-frame-split/`·`data/results/cholec80-frame-split/`에 보존되어 있으며(`ttd.dataset.DATASETS`에는 등록되지 않아 CLI로는 선택되지 않는다), 두 분할의 성능 차이가 곧 시간적 누수의 크기다 — [final-report.md](final-report.md) §11.3.

### 개요

80편의 수술 영상에서 추출한 총 **184,578 프레임** (736 × 480 px), 도구 팁 어노테이션 **315,204개**.

| 스플릿 | 영상 수 | 영상 ID       | 프레임 수 |   비율 |     팁 수 |
| ------ | ------: | ------------- | --------: | -----: | --------: |
| train  |      32 | `video01`–`32` |    71,032 | 38.5 % |   127,662 |
| val    |       8 | `video33`–`40` |    15,312 |  8.3 % |    25,573 |
| test   |      40 | `video41`–`80` |    98,234 | 53.2 % |   161,969 |
| **합계** |  **80** |               | **184,578** | 100 % | **315,204** |

프레임은 원본 영상에서 25프레임(원본 25 fps 기준 초당 1프레임) 간격으로 샘플링됐다.

### 분할: 영상 단위 (`--split-unit video`, 영상 40:10:50)

**한 영상의 모든 프레임이 하나의 스플릿에만 들어간다.** 비율은 프레임 수가 아니라 **영상 편수**에 적용되며, 정렬된 파일명 순서 그대로 잘라 배정한다.

```text
video01 ... video32   →  train  (32편)
video33 ... video40   →  val    ( 8편)
video41 ... video80   →  test   (40편)
```

재현 명령 (`tooltip-annotator` 하위 프로젝트에서 실행):

```bash
python scripts/generate_dataset.py --dataset cholec80 --split-unit video --train 40 --val 10 --test 50
```

`video01–32 / 33–40 / 41–80`은 문헌에서 널리 쓰이는 Cholec80 분할 규약이다. 기본 비율 `60:20:20`을 쓰면 `48 / 16 / 16`편이 되어 이 규약과 달라지므로, **재현하려면 비율 `40 10 50`을 반드시 함께 지정해야 한다.** 이 모드는 난수를 쓰지 않으므로 `--seed`와 파일 경로에 무관하게 같은 결과가 나온다.

두 가지 결과에 유의해야 한다.

1. **시간적 누수가 없다.** 어떤 영상도 두 스플릿에 걸치지 않으므로, test 성능이 곧 **미지의 새 영상에 대한 일반화 성능**이다. `erop`의 test 성능과 달리 낙관적 편향이 없다.
2. **프레임 비율이 영상 비율과 어긋난다.** 영상 길이 편차가 커서 편수 40:10:50이 프레임 수로는 38.5 : 8.3 : 53.2로 나타난다. 특히 **train이 전체의 38.5 %(71,032 프레임)뿐**이어서, 구 프레임 분할(110,747 프레임, 60 %)보다 학습 데이터가 **35.9 % 적다**. 두 분할의 성능 차이를 해석할 때는 누수 제거와 학습 데이터 감소가 함께 작용했음을 감안해야 한다.

### 파일 명명 규칙

```text
{영상ID}_{프레임번호:08d}.{ext}
```

| 구성 요소    | 설명                                 | 예시       |
| ------------ | ------------------------------------ | ---------- |
| `영상ID`     | `video01` ~ `video80`                | `video01`  |
| `프레임번호` | 원본 영상에서의 0-기준 프레임 인덱스 | `00000025` |

평가 스크립트는 파일명에서 마지막 `_` 앞부분을 세션 ID로 쓰므로, cholec80에서는 **영상 1편이 곧 1개 세션**이 된다. 영상 단위 분할에서는 test에 40편만 들어가므로 **세션별 지표가 40개** 산출된다(구 프레임 분할에서는 80개였다).

### 어노테이션 생성

cholec80 원본은 도구 팁 좌표나 픽셀 단위 분할 마스크를 제공하지 않는다. 이 데이터셋의 마스크·팁·바운딩 박스는 erop와 동일한 반자동 파이프라인(사전학습 분할 모델 추론 + contour 휴리스틱)으로 생성됐다. 상세와 그 한계는 [final-report.md](final-report.md)의 데이터셋 장을 참고한다.

## 학습 타겟 생성 방법

본 프로젝트에서는 단순 이진 분할 대신 **히트맵(heatmap)** 을 학습 타겟으로 사용한다. 이 변환은 데이터셋에 관계없이 동일하게 적용된다. `SurgicalToolDataset`의 `target_mode` 인수(학습 스크립트의 `--target-mode`)로 아래 두 생성 방식 중 하나를 고른다.

### `gradient-seg` (기본값) — segmentation mask 필요

**거리 기반 히트맵**. segmentation 마스크의 도구 영역 전체를 팁까지의 거리에 따라 선형으로 채운다.

1. segmentation 마스크의 각 도구 화소에 대해 가장 가까운 팁까지의 거리를 계산한다.
2. 팁 화소: 값 `1.0`
3. 마스크 내에서 팁으로부터 가장 먼 화소: 값 `0.0`
4. 그 사이 화소: 거리에 반비례하여 선형 보간

$$
\text{target}(p) = 1 - \frac{\min_{t \in \text{tips}} \|p - t\|}{\max_{q \in \text{mask}} \min_{t \in \text{tips}} \|q - t\|}
$$

배경 화소(마스크 외부)의 타겟값은 `0.0`이다. 프레임에 도구가 없으면 전체 타겟이 `0.0`이다.

### `gaussian-tip` — 팁 좌표만 필요 (segmentation mask 불필요)

**팁 중심 gaussian 히트맵**. segmentation 마스크를 전혀 사용하지 않고, 각 도구의 팁 좌표를 중심으로 한 2차원 gaussian을 그린다. 여러 도구의 gaussian이 겹치는 화소는 픽셀별 최댓값을 취한다.

$$
\text{target}(p) = \max_{t \in \text{tips}} \exp\left(-\frac{\|p - t\|^2}{2\sigma^2}\right)
$$

- $\sigma$ (학습 스크립트의 `--gaussian-sigma`, 기본 15 px)가 클수록 팁 주변의 넓은 영역에 학습 신호가 퍼진다.
- 팁 화소는 항상 값 `1.0`이며, 프레임에 도구가 없으면 전체 타겟이 `0.0`이다.
- segmentation 레이블링 없이 팁 좌표만으로 학습 데이터를 만들 수 있어, `gradient-seg` 대비 레이블링 비용이 훨씬 낮다. 대신 도구 영역 전체에 대한 정보는 학습에 반영되지 않는다.

두 방식 모두 `MSE(sigmoid(pred[:, 1]), target)` 손실로 학습하며 모델 구조는 동일하다. 체크포인트·평가 결과 저장 경로도 `dataset`·`target_mode`별로 분리된다 (`data/models/<dataset>/<target-mode>/<model-type>/`, `data/results/<dataset>/<target-mode>/<model-type>/`).
