# 모델 구조 설명서: ttd/model/monai_mini.py

`ttd/model/monai_mini.py`에 정의된 경량화 `TooltipDetector`의 아키텍처를 설명한다.
[monai 풀 모델](model-monai.md)과 동일한 전체 구조를 유지하면서 인코더의 블록 수만 절반으로 줄인 버전이다.

## 경량화 전략

### 채택한 방법: 인코더 깊이 축소 (Depth Reduction)

각 스테이지의 MBConv 블록 수를 `ceil(n / 2)`로 줄였다. 채널 폭(width)과 디코더 구조는 변경하지 않았다.

**채널 폭을 유지한 이유**  
채널 폭을 줄이면 스킵 연결 채널 수가 달라져 디코더 `_BLOCK_CFG`를 함께 수정해야 한다.
블록 수만 줄이면 스킵 연결 채널이 그대로이므로 디코더와 분할 헤드를 전혀 건드리지 않아도 된다.

**디코더를 유지한 이유**  
디코더의 연산량은 인코더에 비해 작다. 디코더를 줄이면 세밀한 공간 정보(스킵 연결의 고주파 패턴)를
통합하는 능력이 저하되어 팁 위치 정밀도에 직접적인 영향을 준다. 인코더 깊이만 줄이는 것이
속도와 정확도 사이의 균형에서 더 유리하다.

### 고려했으나 채택하지 않은 방법

| 방법                            | 이유                                                 |
| ------------------------------- | ---------------------------------------------------- |
| 채널 폭 축소 (width reduction)  | 디코더 전체 재설계 필요, 스킵 연결 채널 불일치       |
| 스테이지 수 축소 (fewer stages) | 공간 해상도 단계가 바뀌어 스킵 연결 구조 변경 필요   |
| 디코더 conv 수 축소             | 공간 세부 정보 복원 품질 저하, 팁 위치 정밀도에 민감 |

## 블록 수 비교: 풀 모델 vs 경량 모델

| 스테이지 | 입력 채널 | 출력 채널 | 커널 | 스트라이드 | 풀 블록 수 | 경량 블록 수 | 공간 해상도 |
| -------- | --------- | --------- | ---- | ---------- | ---------- | ------------ | ----------- |
| 0        | 32        | 16        | 3×3  | 1          | 2          | **1**        | H/2         |
| 1        | 16        | 24        | 3×3  | 2          | 3          | **2**        | H/4         |
| 2        | 24        | 48        | 5×5  | 2          | 3          | **2**        | H/8         |
| 3        | 48        | 88        | 3×3  | 2          | 4          | **2**        | H/16        |
| 4        | 88        | 120       | 5×5  | 1          | 4          | **2**        | H/16        |
| 5        | 120       | 208       | 5×5  | 2          | 5          | **3**        | H/32        |
| 6        | 208       | 352       | 3×3  | 1          | 2          | **1**        | H/32        |
| **합계** |           |           |      |            | **23**     | **13**       |             |

축소 비율: 13 / 23 = **56.5 %**

## 전체 구조

풀 모델과 동일하다. 인코더 클래스명만 다르다.

```text
입력 (B, 3, 480, 736)
    │
    ▼
EfficientNetB2MiniEncoder    ← 블록 수 13개 (풀: 23개)
    │  스킵 연결 5개: s0, s1, s2, s4, s6
    ▼
UNetDecoder                  ← 풀 모델과 동일 (5단계)
    │
    ▼
segmentation_head: Conv2d(16 → 2, 3×3)
    │
    ▼
출력 (B, 2, 480, 736)
    ├─ 채널 0: 배경 로짓
    └─ 채널 1: 도구 영역 로짓 (sigmoid → 거리 기반 히트맵)
```

## 디코더 및 분할 헤드

풀 모델과 완전히 동일하다. 스킵 연결 채널 수(16, 24, 48, 120, 352)가 유지되므로 그대로 사용한다.
상세 설명은 [model-monai.md](model-monai.md)의 디코더 및 분할 헤드 절을 참조하라.

## 파라미터 수 비교

| 모델       | 파라미터 수 | 비율   |
| ---------- | ----------- | ------ |
| monai (풀) | 11,450,828  | 100 %  |
| monai_mini | 5,502,870   | 48.1 % |

인코더 블록 수를 56.5 % 줄였을 때 전체 파라미터는 약 48 %로 줄어든다.
디코더와 분할 헤드가 전체 파라미터의 일부를 차지하기 때문에 블록 감소율보다 절감 비율이 다소 작다.

## 입출력 형태 요약

풀 모델과 동일하다.

| 단계        | 텐서 형태         |
| ----------- | ----------------- |
| 입력        | (B, 3, 480, 736)  |
| s0          | (B, 16, 240, 368) |
| s1          | (B, 24, 120, 184) |
| s2          | (B, 48, 60, 92)   |
| s4          | (B, 120, 30, 46)  |
| s6          | (B, 352, 15, 23)  |
| 디코더 출력 | (B, 16, 480, 736) |
| 출력        | (B, 2, 480, 736)  |

## 학습 및 추론

풀 모델과 동일한 손실 함수, 데이터셋, 변환 파이프라인을 사용한다.
`--model-type monai_mini` 인수로 선택한다.

```bash
# 경량 모델 학습
run train-model --model-type monai_mini --epochs 30

# 경량 모델 평가
run eval-model --model-type monai_mini
```

모델 가중치는 `data/models/<dataset>/<target-mode>/monai_mini/best.pt`, `data/models/<dataset>/<target-mode>/monai_mini/last.pt`에 저장된다 (기본 `--target-mode gradient-seg`, `--dataset`은 필수).
평가 결과는 `data/results/<dataset>/<target-mode>/monai_mini/`에 저장된다.
