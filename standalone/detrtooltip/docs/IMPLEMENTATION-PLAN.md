# detrtooltip 구현 계획

수술도구마다 bounding box 하나와 팁 1〜2개를 내는 탐지 모델을 `standalone/detrtooltip`에 새로 만든다. 합성곱 인코더-디코더를 복원 과제로 먼저 사전학습하고, 그 위에 DETR 계열 transformer 헤드를 올려 어노테이션으로 학습한다. 완성된 모델은 `scripts/interactive-trainer.py`에서 쓴다.

- 작성일: 2026-11-23
- 대상 데이터셋: `cholec80`만
- 상태: 구현 완료, 짧은 학습으로 검증함. 본 학습은 미실시 (검증 결과는 [README 6절](../README.md))

## 1. 목표와 범위

| 항목             | 결정                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 1차 목표         | interactive-trainer에서 쓸 **정확한** 모델. 속도와 크기는 우선순위가 낮다                             |
| 객관적 성능 비교 | 지금은 목표가 아니다. 데이터셋 어노테이션이 끝나면 train split만으로 다시 학습해 형제 모델과 비교한다 |
| 출력             | 도구마다 `bbox`, 점수, 팁 `tip`, 선택적인 두 번째 팁 `tip2`                                           |
| 사전학습 가중치  | 쓰지 않는다 (ImageNet 등). 일반 사진 영상이라 복강경 영상에는 도움이 적다                             |
| 의존성           | 루트 `uv` 환경만 사용 (torch, torchvision, numpy, opencv, scipy, tqdm). 형제 프로젝트와 같은 규약     |
| 범위 밖          | erop, 데모 GUI, tooltip-tracker 연동, 속도 최적화                                                     |

## 2. 데이터

### 2.1 split 사용

지금은 성능 측정보다 좋은 모델이 목적이므로 **train, val, test를 모두 학습에 쓴다.** cholec80의 split은 비디오 단위다(video01〜32 train, 33〜40 val, 41〜80 test).

| 단계                      | 사용 프레임                                     |
| ------------------------- | ----------------------------------------------- |
| 1단계 복원 사전학습       | train, val, test 전체 184,578장 (레이블 불필요) |
| 2단계 헤드 학습, 미세조정 | 선택용 비디오(아래)를 뺀 전체                   |
| checkpoint 선택           | test의 **video42** 3,713장 (학습에서 제외)      |

**선택용 비디오를 따로 떼는 이유:** test를 학습에도 쓰고 선택에도 쓰면, 선택 기준이 학습 데이터를 얼마나 외웠느냐가 되어 과적합을 잡지 못한다. 사람이 확인한 test 프레임은 세 비디오에만 있다.

| 비디오  | 이미지 | manual | manual `tip2` 프레임 |  opus | opus `tip2` 프레임 |
| ------- | -----: | -----: | -------------------: | ----: | -----------------: |
| video41 |  3,104 |  1,557 |                  319 | 3,104 |                178 |
| video42 |  3,713 |    448 |                   68 | 3,713 |                174 |
| video54 |  3,101 |     20 |                    7 | 1,821 |                 66 |

video41에는 사람이 확인한 `tip2`의 대부분이 있어 학습에 남긴다. video42는 opus 레이블이 전부 있고 manual도 448장 있어서 선택용으로 쓰기에 알맞다. `--holdout-videos`로 바꿀 수 있고, 빈 값을 주면 모든 비디오로 학습한다.

### 2.2 레이블 출처와 우선순위

프레임마다 레이블 하나를 아래 우선순위로 고른다.

| 우선순위 | 출처                 |                      프레임 수 (전체) | `tip2` | "`tip2` 없음"을 정답으로 쓰는가 |
| -------: | -------------------- | ------------------------------------: | ------ | ------------------------------- |
|        1 | `annotation-manual/` |                                16,154 | 있음   | 예                              |
|        2 | `annotation-opus/`   | 32,204 (manual과 겹치는 2,025장 제외) | 있음   | 예                              |
|        3 | `annotation/`        |                               136,220 | 없음   | **아니오**                      |

- 3순위 `annotation/`의 대부분은 yolov8stooltip의 예측이다. 이 모델은 팁을 하나만 낼 수 있으므로, `tip2`가 없다는 것이 "두 번째 팁이 없다"는 뜻이 아니다. 이 프레임에서는 `tip2` 존재 손실을 걸지 않고, box와 첫 팁만 학습한다.
- opus 자동 어노테이션은 아직 진행 중이다(지금은 video41〜54). opus가 늘어나면 1단계는 그대로 두고 2단계만 다시 학습한다.
- 프레임별 출처는 `per_frame` 메타데이터로 데이터셋이 들고 다녀, 손실이 마스크를 정할 수 있게 한다.

### 2.3 샘플링

`tip2`가 있는 프레임은 약 2,500장으로 전체의 1.4 %다. 그대로 두면 `tip2` 분기가 거의 학습되지 않으므로, 에포크마다 아래 가중치로 복원 추출한다(`WeightedRandomSampler`).

| 프레임 종류                 | 가중치 (출발값) |
| --------------------------- | --------------: |
| `tip2`가 있는 프레임        |              10 |
| 그 밖의 manual, opus 프레임 |               3 |
| `annotation/` 프레임        |               1 |

연속 프레임이 비슷하므로 한 에포크의 길이는 전체 프레임 수가 아니라 `--epoch-size`(출발값 30,000)로 정한다.

## 3. 모델

```text
입력 736 × 480 (원본 해상도, 크기 조정 없음. 두 변 모두 32의 배수)
  │
  ▼ 합성곱 인코더: ResNet-50 bottleneck, 무작위 초기화          ┐
  C2 (/4) · C3 (/8) · C4 (/16) · C5 (/32)                       │ "백본"
  │                                                             │ 1단계에서 사전학습
  ▼ 디코더: FPN (top-down + lateral), 256채널                   │
  P2 (/4) · P3 (/8) · P4 (/16) · P5 (/32)                       ┘
  │
  ├─(1단계 전용) 복원 헤드: P2 → 3×3 Conv → ×4 업샘플 → RGB
  │
  ▼ Deformable DETR 인코더, 6층 (P3〜P5 토큰 7,245개)              ┐
  ▼ 2-stage 제안: 인코더 토큰마다 점수와 박스 → 상위 30개가 쿼리  │
  ▼ Deformable DETR 디코더, 6층, 반복 박스·팁 정제                │ "헤드"
  쿼리마다: 점수, box, 팁 슬롯 A, 팁 슬롯 B, p(B 존재)            │ 2단계에서 학습
  ▼ 팁 정제: P2에서 각 팁 주변 15 × 15 창 → 히트맵 → soft-argmax  ┘
```

| 부분      | 내용                                                                                                                                                |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 인코더    | torchvision `resnet50(weights=None)`의 stem과 4개 스테이지. `--depth 101`로 키울 수 있다                                                            |
| 디코더    | FPN. 1단계에서는 복원 헤드에, 2단계에서는 DETR과 팁 정제에 특징을 준다                                                                              |
| DETR      | Deformable DETR(2-stage, 반복 정제). multi-scale deformable attention은 `grid_sample`로 순수 PyTorch 구현한다(CUDA 확장 없음)                       |
| 쿼리 수   | 30. 한 프레임의 도구 수는 많아야 5개 안팎이다                                                                                                       |
| 팁 표현   | 박스 기준 상대 좌표. 디코더 층마다 박스와 함께 보정한다                                                                                             |
| 팁 정제   | 최종 팁 주변을 stride 4의 P2에서 잘라 작은 Conv로 히트맵을 만들고 soft-argmax로 좌표를 낸다. 회귀만으로는 몇 px 정확도를 내기 어려워 이 단계를 둔다 |
| 출력 규칙 | `tip` = 슬롯 A, `tip2` = 슬롯 B (p(B 존재) > 0.5일 때만). 슬롯 A는 항상 존재한다                                                                    |

파라미터 수는 ResNet-50 인코더 약 23.5M에 FPN과 DETR 헤드를 더해 40M 안팎으로 예상한다. 구현 후 실제 값을 README에 적는다.

### 3.1 백본과 헤드의 경계

이 문서에서 **백본**은 인코더와 FPN 디코더(1단계에서 사전학습하는 부분)이고, **헤드**는 그 뒤의 모든 것(DETR 인코더·디코더, 예측층, 팁 정제)이다. 2단계 전반부와 interactive 모드에서 고정하는 것은 백본이다.

## 4. 1단계: 복원 사전학습

| 항목   | 내용                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 방식   | SimMIM 방식의 마스킹 복원. 입력을 32 × 32 패치로 나눠 60 %를 학습 가능한 mask 토큰 값으로 바꾼다 |
| 손실   | 가려진 패치의 픽셀만 L1. 목표는 패치별로 평균과 분산을 정규화한 픽셀(MAE의 normalized target)    |
| 데이터 | 2.1의 184,578장 전체                                                                             |
| 증강   | 무작위 크기 조정-크롭(원본 해상도 유지), 좌우 반전                                               |
| 산출물 | `data/model/cholec80/pretrain.pt` (백본 가중치와 복원 헤드)                                      |

**가리지 않는 오토인코더를 쓰지 않는 이유:** FPN에는 해상도별 skip 연결이 있어, 입력을 그대로 복사하는 것만으로 복원 손실을 줄일 수 있다. 가리면 주변 맥락으로 내용을 추론해야 하므로 쓸모 있는 특징을 배운다.

**위험:** 마스킹으로 사전학습한 CNN은 가리지 않은 입력에서 특징 분포가 달라지는 문제가 알려져 있다(SparK, ConvNeXt V2가 sparse conv로 다룬 문제). 여기서는 단순한 구현으로 시작하고, 2단계에서 **무작위 초기화 백본과 비교**해 사전학습이 실제로 도움이 되는지 확인한다(7.2).

## 5. 2단계: 어노테이션 학습

### 5.1 순서

처음 계획은 헤드만 학습(백본 고정)한 뒤 전체를 미세조정하는 두 단계(2a, 2b)였다. 짧은 학습(각 3 에포크 × 8천 장)에서 헤드만 학습한 쪽이 모든 에포크에서 뒤처져(video42 tool AP50 0.592 대 0.803), 2026-11-23 사용자 승인으로 **헤드만 학습하는 단계를 없앴다.** 헤드 단독 학습이 막으려던 문제, 즉 무작위 헤드의 큰 그래디언트가 사전학습 백본을 흔드는 문제는 백본 학습률 0.1배와 500 step warmup이 맡는다.

| 학습 대상 | 백본                                   | 학습률 (출발값)      |
| --------- | -------------------------------------- | -------------------- |
| 전체      | 1단계 가중치에서 시작, BN 통계는 고정 | 헤드 1e-4, 백본 1e-5 |

옵티마이저는 AdamW(weight decay 1e-4), 그래디언트 클리핑 0.1, EMA, AMP(손실과 attention 샘플링은 fp32)를 쓴다. 기본값은 30 에포크 × 3만 장이다.

interactive 모드(7절)에서는 지금처럼 백본을 고정하고 헤드만 학습한다.

### 5.2 매칭과 손실

헝가리안 매칭 비용은 분류(focal), 박스 L1, GIoU, 팁 L1의 합이다. 매칭된 쿼리에 다음 손실을 건다. 디코더 각 층과 2-stage 제안에도 같은 손실(보조 손실)을 건다.

```text
L = 2·L_focal + 5·L_box_L1 + 2·L_GIoU + λ_tip·L_tip + λ_ex·L_exist      (λ_tip 5, λ_ex 1 출발값)
```

- **팁 손실 (순서 무관):** 좌표는 프레임 크기로 정규화한 L1이다.
  - 정답 팁이 둘 `{t1, t2}`이면 `min(|A−t1| + |B−t2|, |A−t2| + |B−t1|)`.
  - 정답 팁이 하나 `{t1}`이면 `|A−t1|`. 슬롯 B의 좌표에는 손실이 없다.
- **`tip2` 존재 손실:** p(B 존재)에 BCE를 건다. 정답은 팁 개수가 2인지다. 2.2에서 "예"인 출처(manual, opus)에서만 걸고, `annotation/` 프레임은 마스크한다.
- **팁 정제:** 정제 전 좌표와 정제 후 좌표 모두에 팁 손실을 건다.

### 5.3 증강

좌우 반전, HSV, 무작위 크기 조정-크롭. 반전은 팁 순서와 무관하므로 그대로 쓸 수 있다. DETR 계열은 모자이크 없이도 학습되므로 넣지 않는다.

## 6. checkpoint 선택과 평가

- **선택 기준:** video42에서 팁 F1 @ 20 px(헝가리안, conf 0.5). `tip`과 `tip2`를 모두 정답 점으로 넣는다. 가장 높은 에포크를 `model.pt`로 저장한다.
- **`eval-model.py` 지표:**
  - 탐지: `tool` AP@0.5, AP@0.5:0.95.
  - 팁: Hit-rate @ 10/20/50 px, 거리 통계. yolov8stooltip의 `tipmetrics.py`를 복사해 쓴다.
  - 도구-팁 쌍: yolov8stooltip의 own tip @ N px. 두 팁 중 가까운 것으로 판정한다.
  - `tip2`: 존재 P/R/F1 (manual, opus 프레임만), `tip2` hit-rate @ N px (순서 무관 매칭).
- **참고 비교:** 같은 video42 프레임에서 yolov8stooltip의 수치도 함께 낸다. 이 비교는 interactive-trainer의 기본 모델을 바꿀지 판단하는 근거일 뿐, 객관적 성능 비교는 아니다(1절).

## 7. interactive-trainer 연동

### 7.1 checkpoint 형식

```python
{
    "family": "detrtooltip",       # 새 필드. Runner 선택에 쓴다
    "model": state_dict,
    "arch": {"depth": 50, "num_queries": 30, ...},
    "image_size": [736, 480],
    "class_names": ["tool"],
    "dataset": "cholec80",
    "epoch": ..., "stage": "train",
}
```

### 7.2 Runner

- `ModelRunner.open`은 `checkpoint.get("family")`를 먼저 보고, 없으면 지금처럼 `kpt_shape`로 기존 두 계열을 구분한다.
- `DetrRunner(ModelRunner)`를 새로 만든다.
  - `_build`: 모델과 손실을 만들고 **백본의 `requires_grad`를 끈다.** 기반 클래스는 `_build` 다음에 `requires_grad`인 파라미터만으로 옵티마이저를 만들므로, 헤드만 학습된다.
  - `predict`: letterbox 없이 원본 해상도로 추론하고, `tip2`가 있는 annotation 목록을 돌려준다.
  - `train` 내부의 배치 구성(`_label_rows`, `_training_batch`)은 YOLO 형식 target을 가정하므로 DETR용 target(프레임별 박스, 팁 목록, 존재 마스크)으로 바꿔 구현한다.
- `import_common`은 `boxes`, `dataset`, `loss`, `model` 모듈을 읽는다. detrtooltip의 `common/`도 같은 이름을 쓴다.
- interactive-trainer 화면에서 고른 모델은 `data/itrainer-model/`에 둔다. 학습이 끝난 `model.pt`를 `detrtooltip.pt`로 복사해 쓴다.

### 7.3 선행 작업

interactive-trainer는 지금 `tip2`와 `label`을 읽지 않고, 저장할 때 지운다. detrtooltip을 연결하기 전에 다음이 먼저 되어야 한다.

1. `tip2`와 `label` 보존 (읽기, 편집, 저장).
2. `tip2` 표시, 그리고 `agreement_score`의 순서 무관 팁 거리.

이 둘이 없으면 detrtooltip이 낸 `tip2`가 "Update" 후 저장할 때 사라진다.

## 9. 검증 계획

| 항목                                        | 확인 방법                                                                              |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| 모델 생성, 파라미터 수, 순전파·역전파 (AMP) | 무작위 입력으로 출력 모양과 그래디언트 흐름 확인                                       |
| 레이블 우선순위, 마스크                     | 출처별 표본 프레임에서 데이터셋이 고른 레이블과 마스크를 파일과 대조                   |
| 증강 후 박스·팁 정렬                        | 증강한 표본을 그려 확인                                                                |
| 순서 무관 손실                              | 팁 순서를 바꾼 정답에서 손실이 같은지 단위 확인                                        |
| 복원 사전학습                               | 작은 이미지 집합에 과적합시켜 복원 손실이 0 가까이 내려가는지, 복원 결과를 그려 확인   |
| 2단계 학습이 실제로 되는지                  | 짧은 학습 뒤 video42의 tool AP와 팁 hit@20                                             |
| 사전학습 효과                               | 같은 짧은 2단계 학습을 무작위 초기화 백본으로 한 결과와 비교                           |
| interactive-trainer 연동                    | `DetrRunner`로 불러 `predict` 한 번, `train` 몇 단계, checkpoint 저장 후 다시 불러오기 |

본 학습(긴 1단계, 2단계)은 짧은 학습 결과를 확인받은 뒤 진행한다. GPU는 cuda:1〜3을 쓴다(cuda:0은 PCIe 대역폭 문제로 쓰지 않는다).

## 10. 가정과 열린 질문

사용자와 정하지 않고 이 문서에서 가정한 것이다. 구현 전에 바꿀 수 있다.

- **선택용 비디오 video42 분리 (2.1):** "test로 checkpoint를 선택한다"는 결정을, 학습에서 뺀 test 비디오 하나로 고르는 것으로 해석했다.
- **레이블 우선순위와 `tip2` 마스크 (2.2):** manual > opus > `annotation/`, 존재 손실은 manual과 opus에서만.
- **GPU 하나로 학습:** DDP는 넣지 않는다. 1단계 처리 속도를 잰 뒤 시간이 너무 길면 `--frame-stride`나 DDP를 검토한다.
- **크기:** ResNet-50으로 시작한다. 성능이 모자라면 ResNet-101을 시험한다.
- **하이퍼파라미터:** 마스크 비율, 학습률, 손실 가중치, 샘플링 가중치, 쿼리 수, 팁 정제 창 크기는 근거 있는 출발값일 뿐 튜닝하지 않았다.
