# YOLO26 실험결과 분석 보고서

> 대상: [baseline/yolo26](../README.md). Ultralytics가 공개한 YOLO26을 이 저장소의 복강경
> 어노테이션으로 직접 학습하고, 루트 프로젝트와 같은 매칭 규칙으로 채점한 결과다.
> 모델과 학습 루프는 `ultralytics` 8.4.131의 것이며, 재구현이 아니다.
>
> 이 문서의 모든 수치는 [summary-results.md](summary-results.md)에 있고, 그 문서는
> `scripts/generate-summary.py`가 `data/model/`·`data/results/`에서 다시 계산한다.
> 비교 대상인 형제 베이스라인·루트 프로젝트의 수치는 각 프로젝트의 보고서에서 인용했다.

## 요약

- **팁 좌표의 정밀도가 지금까지 시험한 모든 모델 중 가장 높다.** 오차 중앙값이 cholec80
  3.31 px, erop 1.90 px로 YOLOv8s 클론(3.60 px, 2.04 px)보다 작고, 루트 프로젝트의 최고
  모델(5.39 px, 7.81 px)의 절반 이하다.
- **cholec80에서는 Hit@10 px 61.57 %로 전 모델 최고**이고, erop에서는 74.59 %로 YOLOv8s
  클론(75.91 %)에 근소하게 뒤진다. 데이터셋에 따라 순위가 갈린다.
- **AP@0.5는 지지만 AP@0.5:0.95는 이긴다.** 두 데이터셋 모두에서 mAP@0.5는 YOLOv8s 클론보다
  낮고(0.735 대 0.751, 0.848 대 0.858) mAP@0.5:0.95는 높다(0.564 대 0.552, 0.701 대 0.685).
  상자를 덜 찾는 대신 찾은 상자는 더 정확하다는 뜻이며, 팁 오차 중앙값이 작은 것과 같은 성질이다.
- **이 비교는 YOLO26에 유리한 쪽으로 기울어 있다.** 이번 학습은 COCO 사전학습 가중치에서
  시작했고, 비교 대상인 YOLOv8s 클론과 CLAD-Net은 무작위 초기화에서 학습했다.
  **사전학습 이점을 안고도 탐지 AP@0.5에서 앞서지 못했다**는 것이 이 보고서의 가장 중요한
  단서다 (§6).
- **NMS를 없앴는데 오탐이 줄지 않았다.** cholec80 헝가리안 10 px 기준 오탐이 40,315개로
  YOLOv8s 클론(30,699)보다 31 % 많다. end-to-end 헤드의 이점이 이 과제에서는 정밀도로
  나타나지 않았다 (§4).
- **150 에포크는 크게 과하다.** 최고점이 cholec80 64 에포크, erop 103 에포크이고, 그 뒤로는
  각각 86·47 에포크 동안 갱신이 없었다. 사전학습에서 시작하는 만큼 수렴이 빠르다 (§2).

## 1. 실험 설정

| 항목             | 값                                                                              |
| ---------------- | ------------------------------------------------------------------------------- |
| 아키텍처         | YOLO26s: C3k2 백본 + SPPF + C2PSA + 앵커프리 end-to-end 헤드                    |
| 파라미터         | **9,949,412** (2클래스)                                                         |
| 추론 후처리      | **없음.** 객체당 상자 하나를 헤드가 직접 내므로 NMS도 IoU 임계값도 쓰지 않는다  |
| 박스 회귀        | DFL 없음 (`reg_max=1`), 세 번째 손실항이 `l1_loss`                              |
| 클래스           | `tool`(어노테이션 bbox), `tip`(팁 좌표 중심 **32 × 32 px** 상자)                |
| 입력             | 640 × 640 letterbox (원본 736 × 480)                                            |
| 라벨 할당        | one2many(topk 10)와 one2one(topk 7) 두 분기                                     |
| 손실             | 두 분기의 가중합. one2many 가중치가 학습 중 0.8에서 0.1로 감쇠                  |
| 에포크           | **150** (`--patience 0`, 조기 종료 없음)                                        |
| 배치 / 옵티마이저 | 16 / `auto` (이 규모에서 **MuSGD**로 해석되며 `--lr 0.01`은 무시된다)          |
| 혼합 정밀도      | 사용                                                                            |
| `--frame-stride` | **5** (학습 프레임 5장 중 1장)                                                  |
| `--val-frames`   | 2,000 (상한)                                                                    |
| 사전학습         | **COCO `yolo26s.pt`** (형제 베이스라인 두 개는 무작위 초기화)                   |

팁 박스 32 px, `--frame-stride 5`, 150 에포크, 640 × 640 입력은
[yolov8sclone](../../yolov8sclone/docs/experimental-results.md)·[cladnet](../../cladnet/docs/experimental-results.md)과
같은 값으로 맞췄다. **다른 것은 사전학습 하나뿐이다.**

### 데이터

| 데이터셋   | train (stride 5 적용) |                  val | 실제 val 프레임 |   test | test GT 팁 |         test 세션 |
| ---------- | --------------------: | -------------------: | --------------: | -----: | ---------: | ----------------: |

학습에 실제로 들어간 상자는 cholec80이 `tool`·`tip` 각 25,622개, erop이 각 30,328개다.
도구가 하나도 없는 프레임도 배경 표본으로 포함된다 (cholec80 1,141장, erop 4,614장).

cholec80은 **영상 단위로 분리된** 스플릿(video01〜32 train / 33〜40 val / 41〜80 test)이다.
erop은 영상 내부를 프레임 단위로 섞어 나눈 스플릿이라 인접 프레임이 train과 test에 함께
들어간다(시간적 누수). **erop 수치는 cholec80보다 낙관적으로 읽어야 한다.**

평가는 준비된 YOLO 데이터셋이 아니라 `data/dataset/`의 원본 프레임과 어노테이션을 직접
읽으므로, 위의 준비 인수와 무관하게 test 전수(98,234 / 36,142 프레임)로 측정됐다.

**사전학습의 효과가 1 에포크에서 그대로 드러난다.** 첫 에포크에 이미 mAP@0.5 0.606(cholec80),
0.667(erop)이다. 같은 시점에 YOLOv8s 클론과 CLAD-Net은 둘 다 0.000이고, 2 에포크에 가서야
각각 0.456과 0.125에 닿는다. 무작위 초기화에서 두 에포크가 걸리던 지점을 여기서는 첫 에포크에
통과하고, 그 값도 더 높다.

**대신 최종 도달점의 이득은 없다.** cholec80 최고 mAP@0.5가 0.775로 YOLOv8s 클론의 0.735와
비슷하고, erop은 0.849 대 0.900으로 오히려 낮다. 사전학습은 수렴을 앞당겼을 뿐 종착점을
올리지 못했다.

**과적합이 뚜렷하다.** val loss의 실제 최저점은 cholec80 42 에포크(1.9097), erop 84 에포크
(1.4304)이고, 거기서 150 에포크의 2.1715·1.5104까지 다시 오른다. mAP도 함께 내려간다. 최고 에포크가 64인데 그 뒤로 86 에포크를 더 돌린 셈이다.
학습 프레임이 14,207·21,685장뿐인 데다 사전학습에서 시작해 초기 수렴이 빠르므로, 데이터를
소진하는 시점도 그만큼 빠르다. **이 설정에서는 70〜110 에포크면 충분하다.** `model.pt`는
최고점에서 저장되므로 아래 보고된 성능 자체는 영향을 받지 않는다.

> 학습 시간은 참고용이다. 두 학습이 서로 다른 GPU에서 돌았고 그중 하나는 호스트 전송
> 대역폭이 낮은 장치였으므로, 에포크당 시간을 두 데이터셋 사이에서 비교하면 안 된다.

## 3. 탐지 성능 (test 전수)

`conf=0.25`, `max_det=300`. AP 곡선은 `conf=0.001`까지 내려가며 계산했다. NMS는 없다.

| 데이터셋   | mAP@0.5 | mAP@0.5:0.95 | tool AP@0.5 | tool AP@0.5:0.95 | tip AP@0.5 | tip AP@0.5:0.95 |
| ---------- | ------: | -----------: | ----------: | ---------------: | ---------: | --------------: |
| `cholec80` |  0.7348 |       0.5644 |      0.8268 |           0.7038 |     0.6427 |          0.4250 |
| `erop`     |  0.8476 |       0.7011 |      0.8922 |           0.8121 |     0.8029 |          0.5901 |

`tip` AP@0.5가 0.64·0.80으로 `tool`(0.83·0.89)에 크게 뒤지지 않는다. 팁 상자를 32 px로 키운
효과이며, 형제 베이스라인들과 같은 경향이다.

**AP@0.5와 AP@0.5:0.95의 방향이 갈린다.** YOLOv8s 클론과 견주면 AP@0.5는 두 데이터셋 모두
낮은데(−0.016, −0.010) AP@0.5:0.95는 모두 높다(+0.012, +0.016).

| 지표 (cholec80) | YOLO26     | YOLOv8s 클론 |
| --------------- | ---------: | -----------: |
| mAP@0.5         |     0.7348 |   **0.751**  |
| mAP@0.5:0.95    | **0.5644** |      0.552   |
| tool AP@0.5:0.95 | **0.7038** |     0.696   |
| tip AP@0.5:0.95 | **0.4250** |      0.408   |

IoU 0.5에서 세는 상자 수는 적은데 IoU를 0.95까지 올려도 살아남는 비율은 높다. **상자의 개수가
아니라 정확도에서 앞선다**는 뜻이고, 이것이 §4의 팁 오차 중앙값과 같은 현상의 다른 표현이다.
DFL을 없애고 `l1_loss`로 좌표를 직접 회귀하는 YOLO26의 설계와 방향이 맞는 결과다.

> **주의**: `summary.json`의 클래스별 `precision`(`tool` 0.15·0.25, `tip` 0.05·0.07)은 AP 곡선을
> 그리기 위해 `conf=0.001`까지 누적한 값이라 운용 지점의 정밀도가 아니다. 운용 지점은 §4의
> 헝가리안 표를 본다.

### 읽는 법

**정밀도(오차의 크기)에서 전 모델 최고다.** 오차 중앙값 3.31 px·1.90 px는 지금까지 이 저장소에서
측정한 어떤 모델보다 작다. 헝가리안 10 px 매칭의 평균 오차도 2.52 px·1.97 px로 가장 작다.
가장 가까운 경쟁자인 YOLOv8s 클론보다 7〜8 % 더 작다.

**cholec80에서는 재현율도 가장 높다.** TP 99,687개는 YOLOv8s 클론보다 2,771개, `gaussian-tip`보다
3,390개 많다. 영상 단위로 분리돼 일반화가 실제로 시험되는 스플릿에서 앞섰다는 점이 의미가 있다.

**그런데 오탐이 많다.** cholec80 FP 40,315개는 YOLOv8s 클론(30,699)의 1.31배, `gaussian-tip`
(28,526)의 1.41배다. 그 결과 정밀도가 0.712로 CLAD-Net을 빼면 가장 낮다.
**NMS를 없앤 end-to-end 헤드가 오탐을 줄여 줄 것이라는 기대는 이 데이터에서 성립하지 않았다.**
one2one 분기가 객체당 상자를 하나로 줄이는 것은 맞지만, 그 판단이 전적으로 클래스 점수에
맡겨져 있어 `conf=0.25`라는 임계값 하나가 정밀도를 결정한다. 조정할 IoU 임계값이 없는 만큼
**`--conf`가 이 모델에서 유일하면서 그만큼 더 중요한 운용 손잡이다** (§8).

**데이터셋에 따라 순위가 갈린다.** cholec80에서는 YOLOv8s 클론을 모든 팁 지표에서 앞서지만,
erop에서는 중앙값을 뺀 전부에서 뒤진다. erop은 시간적 누수가 있는 스플릿이라 학습 데이터를
얼마나 잘 외웠는지가 더 크게 반영되는데, 사전학습에서 출발한 이 모델이 오히려 그 축에서 손해를
본 것으로 보인다.

**꼬리에서는 여전히 히트맵 모델에 진다.** Hit@50 px가 cholec80 73.31 %로 `gradient-seg`(76.12 %)에
못 미치고 P90도 크다. "정확히 짚거나 아예 없거나"인 탐지기의 성향은 YOLO26에서도 그대로다.

**다른 것은 초기 가중치 하나뿐이고, 그 하나가 YOLO26 쪽에 유리하다.**

**세 가지를 읽을 수 있다.**

   mAP@0.5와 tip AP@0.5에서 2년 전 아키텍처인 YOLOv8s에 두 데이터셋 모두 뒤진다.
   **같은 조건(`--no-pretrained`)에서 다시 재면 격차가 더 벌어질 가능성이 크다.**
2. **이기는 축은 일관되게 "정확도"다.** mAP@0.5:0.95, 팁 오차 중앙값, 헝가리안 평균 오차처럼
   찾은 것이 얼마나 정확한지를 재는 지표에서는 모두 앞선다. DFL을 없애고 좌표를 직접
   회귀하는 설계, 그리고 C2PSA로 백본 말단에 attention을 넣은 설계가 이 방향과 맞는다.
3. **CLAD-Net은 모든 축에서 확실히 뒤진다.** 조건 차이를 감안하더라도 격차가 크다. 논문이
   주장하는 "더 적은 파라미터로 더 빠르고 정확하다"는 성질은 이 데이터·이 과제에서
   두 YOLO 계열 모델 어느 쪽과 견주어도 재현되지 않았다.

> **미실행 실험 하나가 이 비교의 결론을 바꿀 수 있다.** `--no-pretrained` 학습은
> [commands.md](commands.md) §3에 명령이 준비돼 있지만 아직 돌리지 않았다.
> 그것을 돌리기 전까지 위 표의 "YOLO26이 앞선 지표"는 **아키텍처의 공로와 사전학습의 공로를
> 나눌 수 없다.**

## 7. 속도

`eval-model`이 test 전수를 처리하며 측정한 값이다.

| 데이터셋   | 장치   | 프레임당 |   FPS |
| ---------- | ------ | -------: | ----: |
| `cholec80` | cuda:2 |  6.78 ms | 147.6 |
| `erop`     | cuda:1 |  7.72 ms | 129.5 |

> cholec80은 이전에 다른 장치에서 7.37 ms로 측정됐으나, 그 장치는 PCIe 대역이 절반이라
> 속도 비교에 쓸 수 없었다. 같은 체크포인트를 정상 장치에서 다시 재 6.78 ms를 얻었고,
> **정확도 지표는 소수점까지 전부 동일했다.** 장치 차이가 이 워크로드에 남기는 몫은 8 %다.

### 모델 비교

> 네 모델을 **같은 장치(RTX A6000 cuda:2), 같은 프레임(cholec80 test 60장), 같은 구간**으로
> 쟀다. 미리 letterbox해 장치에 올려 둔 뒤 forward + 디코딩 + 후처리만 5회 반복 평균한
> 값이라 위 표보다 작다. `fused`는 Conv+BN을 합성곱에 접은 상태이며, Ultralytics는
> `AutoBackend`가 로드할 때 이것을 자동으로 한다: **실제로 돌아가는 것은 fused 열이다.**

| 모델                        |    파라미터 |  unfused |       fused | fuse 개선 |
| --------------------------- | ----------: | -------: | ----------: | --------: |
| **YOLO26 (참조 구현)**      |   9,949,412 |  9.32 ms | **5.93 ms** |      36 % |
| YOLO26 클론 (배포 구성)     |   9,949,412 |  7.73 ms |     5.96 ms |      23 % |
| YOLOv8s 클론                |  11,136,374 |  5.51 ms | **4.62 ms** |      16 % |
| CLAD-Net                    |   7,488,483 | 10.22 ms |     8.44 ms |      17 % |

**파라미터가 11 % 적고 NMS까지 없는데 YOLOv8s 클론보다 28 % 느리다.** 이전 판이 13〜19 %로
적은 것은 장치와 fuse 조건이 섞인 비교였기 때문이고, 조건을 맞추면 격차가 더 벌어진다.
원인은 파라미터로 드러나지 않는 연산이다: C2PSA의 attention 블록이 백본 말단에 붙고,
추론에서도 one2many 분기가 계산된다(`Detect.forward`가 두 분기를 모두 만든 뒤 one2one만
후처리한다). 클론에서 그 분기를 건너뛰면 7.73 → 5.96 ms로, 약 1.8 ms가 회수된다.

다만 CLAD-Net보다 1.42배 빠르고, **160 FPS는 30 FPS 영상 실시간 처리에 넉넉하다.**

**fuse에서 가장 많이 얻는 모델이다**(36 %). 같은 아키텍처를 재구현한 클론이 23 %에
그치는 이유는 밝히지 못했다. `bn`을 `nn.Identity()`로 남기는 대신 `forward`를 통째로
바꿔 호출을 없애 보았으나 2 %에 그쳤다.

## 8. 결론과 다음 단계

### 결론

1. **팁 좌표 정밀도에서 이 저장소 최고 기록이다.** 오차 중앙값 1.90〜3.31 px로 형제
   베이스라인과 루트 프로젝트의 모든 모델을 앞선다. 정밀 좌표가 필요한 응용(로봇 제어, 계측)에
   가장 적합한 후보다.
2. **탐지 AP@0.5에서는 YOLOv8s에 뒤지고, 그 비교는 YOLO26에 유리하게 기울어 있었다.**
   사전학습 이점을 뺀 동일 조건 비교가 남아 있으며, 그 전까지 "최신 모델이 더 낫다"고 말할
   근거는 없다.
3. **NMS 제거가 정밀도로 돌아오지 않았다.** cholec80 오탐이 YOLOv8s 클론보다 31 % 많다.
   조정할 IoU 임계값이 없어진 만큼 `--conf` 하나가 운용 성능을 좌우한다.
4. **150 에포크는 필요 이상이다.** 최고점이 64·103 에포크이고 그 뒤는 과적합 구간이다.
   사전학습에서 출발하면 데이터를 더 빨리 소진한다.
5. **남은 최대 약점은 다중 도구 프레임의 과소 탐지다.** 큰 오차의 85〜89 %가 여기서 나오고,
   지금까지 시험한 네 접근 모두 같은 문제를 안고 있다. end-to-end 헤드도 예외가 아니었다.

### 다음 단계 (효과가 클 것으로 보이는 순서)

1. **`--no-pretrained` 학습.** 이 보고서의 §6이 결론을 내지 못하는 유일한 이유다. 명령은
   [commands.md](commands.md) §3에 이미 있고, 산출물을 `data/model-scratch/`로 분리하면
   기존 결과를 덮지 않는다. **가장 먼저 해야 할 실험이다.**
2. **신뢰도 임계값 스윕.** NMS가 없는 이 모델에서 `--conf`는 유일한 운용 손잡이인데
   `conf=0.25`는 Ultralytics 기본값일 뿐이다. 0.1〜0.5 구간을 훑으면 탐지 실패율과 오탐의
   맞교환 곡선을 얻는다. §4에서 본 정밀도 열세가 임계값 선택의 문제인지 모델의 문제인지가
   여기서 갈린다.
3. **에포크를 70〜110으로.** §2에서 과적합 시작점을 확인했다. 학습 시간을 3분의 1 이상
   줄이면서 같은 성능을 얻는다.
4. **과소 탐지 대응.** 큰 오차의 85〜89 %를 차지한다. one2one 분기의 `topk`(현재 7)를 올려
   GT마다 양성 후보를 늘리거나, `tip` 클래스에 별도 임계값을 두는 방법을 시험할 수 있다.
5. ~~**같은 장치에서의 속도 재측정.**~~ **완료했다.** cholec80을 정상 장치에서 다시 재
   7.37 → 6.78 ms를 얻었고(정확도 지표는 전부 동일), 네 모델을 한 장치·한 구간으로 묶은
   비교표를 §7에 넣었다.
6. **입력 캔버스 모양.** 640 × 640 letterbox는 34.8 %가 패딩이다. 800 × 512로 바꾸면 같은
   연산량에서 물체가 23 % 커진다
   ([CLAD-Net 보고서 부록 B](../../cladnet/docs/experimental-results.md)). 팁처럼 작은 물체가
   대상이므로 이 베이스라인에서도 효과가 있을 수 있다.

## 재현 명령

```bash
# 데이터셋 준비 (완료됨: data/yolo/<dataset>/에 산출물이 있다)
./baseline/yolo26/run prepare-dataset --dataset cholec80
./baseline/yolo26/run prepare-dataset --dataset erop

# 학습 (완료됨: data/model/<dataset>/에 산출물이 있다)
./baseline/yolo26/run train-model --dataset cholec80 --device cuda:1 --workers 12
./baseline/yolo26/run train-model --dataset erop     --device cuda:0 --workers 12

# 평가 (완료됨: data/results/<dataset>/test/에 산출물이 있다)
./baseline/yolo26/run eval-model --dataset cholec80 --split test --device cuda:0
./baseline/yolo26/run eval-model --dataset erop     --split test --device cuda:1

# 이 보고서가 인용하는 수치 표 재생성
./baseline/yolo26/run generate-summary
```

§8의 1번(스크래치 학습)은 **아직 실행하지 않았다.** 명령은 다음과 같으며, 출력을 분리하므로
위의 결과를 덮지 않는다.

```bash
./baseline/yolo26/run train-model --dataset cholec80 --no-pretrained \
    --output-dir data/model-scratch/cholec80 --device cuda:1
./baseline/yolo26/run eval-model  --dataset cholec80 --split test \
    --model data/model-scratch/cholec80/model.pt \
    --output-dir data/results-scratch/cholec80/test --device cuda:1
./baseline/yolo26/run generate-summary --suffix "-scratch" --output docs/summary-scratch.md
```
