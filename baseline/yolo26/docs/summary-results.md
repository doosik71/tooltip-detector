모든 값은 `data/` 아래 파일에서 다시 계산된다.

## 2. 학습 설정

`train-status.json`의 `args`(실행 인수)와 `info`(데이터셋 준비 단계에서 정해져
체크포인트에 기록된 값)를 그대로 옮긴 것이다. 보고서의 실험 설정 표는 여기서 만든다.

| 항목            | `cholec80` | `erop` |
| --------------- | ---------- | ------ |
| `scale`         | s          | s      |
| `epochs`        | 150        | 150    |
| `batch_size`    | 16         | 16     |
| `image_size`    | 640        | 640    |
| `optimizer`     | auto       | auto   |
| `lr`            | 0.01       | 0.01   |
| `patience`      | 0          | 0      |
| `no_pretrained` | False      | False  |
| `no_amp`        | False      | False  |
| `device`        | cuda:1     | cuda:0 |
| `workers`       | 12         | 12     |
| `tip_box_size`  | 32.0       | 32.0   |
| `frame_stride`  | 5          | 5      |
| `pretrained`    | True       | True   |

> `optimizer=auto`는 이 규모의 학습에서 MuSGD로 해석되며, 그때 `lr`은 무시되고
> Ultralytics가 정한 값이 쓰인다. `tip_box_size`와 `frame_stride`는 학습 인수가
> 아니라 `prepare-dataset` 단계에서 정해진 값이다.

## 4. 탐지 성능

평가 조건: `conf=0.25`, `max_det=300`, AP 곡선은 `conf=0.001`까지, 입력 640 px, split `test`.
YOLO26은 end-to-end 헤드라 NMS가 없고, 따라서 IoU 임계값도 없다.

## 8. 예측 신뢰도 분포

`per_tip.csv`의 `score` 열이다. **분포가 잘려 있다** — 평가가 `conf`
0.25 로 실행되어 그보다 낮은 예측은 애초에 기록되지 않았다.
따라서 아래 `≥ 0.25` 열은 임계값이 0.25 이상이면 항상 100 %가 되며,
잘리지 않은 분포를 보려면 `--conf`를 낮춰 `eval-model`을 다시 돌려야 한다.

| 데이터셋   | 표본       |       n |   p10 | 중앙값 |   p90 |  최대 |  ≥ 0.25 |
| ---------- | ---------- | ------: | ----: | -----: | ----: | ----: | ------: |
| `cholec80` | 전체 매칭  | 149,895 | 0.328 |  0.749 | 0.899 | 0.948 | 100.0 % |
| `cholec80` | 10 px 이내 |  99,733 | 0.364 |  0.792 | 0.904 | 0.948 | 100.0 % |
| `erop`     | 전체 매칭  |  47,851 | 0.411 |  0.833 | 0.910 | 0.948 | 100.0 % |
| `erop`     | 10 px 이내 |  37,830 | 0.472 |  0.848 | 0.912 | 0.948 | 100.0 % |

> YOLO26에도 objectness 항이 없고 클래스 점수가 곧 신뢰도다. 게다가 헤드가
> end-to-end라 한 객체에 박스 하나만 남기므로, 중복 박스를 걸러 내던 NMS가
> 하던 일을 점수 자체가 떠안는다. 최대 신뢰도가 0.9 부근까지 올라오는지 본다.

## 10. 속도

`eval-model`이 프레임 한 장을 처리한 실제 시간이다 — letterbox, forward,
디코딩을 모두 포함한다(YOLO26은 NMS가 없다). GPU가 다르면 비교할 수 없다.

## 11. 이 문서에서 만들 수 없는 값

보고서에 필요하지만 위 두 디렉터리만으로는 나오지 않는 것들이다. 추측해 넣지 않는다.

- **다른 모델과의 비교** — 루트 프로젝트나 형제 베이스라인의 수치. 이 스크립트는
  자기 서브 프로젝트의 `data/`만 읽는다.
- **신뢰도 임계값 스윕** — `--conf`를 바꿔 `eval-model`을 여러 번 돌린 결과가 필요하다.
- **동일 조건 속도 비교** — 모델마다 다른 GPU에서 측정된 값이라, 같은 장치에서 다시
  재야 비교할 수 있다.
- **데이터셋 규모** — train/val 프레임 수는 `data/dataset/`을 읽어야 나온다.
- **파라미터 수의 근거** — 위 §1의 값은 파일이 아니라 학습된 체크포인트를 열어 센 것이다.
