# YOLOv8s 실험결과 분석 보고서

> 대상: [baseline/yolov8sclone](../README.md) — YOLOv8s를 `ultralytics` 없이 순수 PyTorch로
> 재구현하고, 이 저장소의 어노테이션으로 처음부터 학습한 것. 이하 **YOLOv8s**로 부르며,
> 사전학습 가중치를 그대로 쓰는 [baseline/yolov8s](../../yolov8s/README.md)와는 다른 모델이다.
>
> 이 문서의 모든 수치는 [summary-results.md](summary-results.md)에 있고, 그 문서는
> `scripts/generate-summary.py`가 `data/model/`·`data/results/`에서 다시 계산한다.

## 요약

- **팁 좌표 산출에서 tooltip-detector와 대등하거나 낫다.** cholec80 test에서 Hit@10 px 59.9 %
  (루트 프로젝트 최고 모델 59.6 %), erop에서 75.9 % (69.5 %)다. 오차 중앙값은 3.60 px, 2.04 px로
  루트 프로젝트(5.39 px, 7.81 px)보다 작다.
- **CLAD-Net보다 모든 지표에서 앞선다. 이번에는 조건이 같다.** 두 베이스라인이 같은 팁 크기
  (32 px), 같은 프레임 샘플링(stride 5), 같은 에포크(150)로 학습됐으므로 **아키텍처 비교가
  성립한다** (§6).
- **속도가 1.8배 빠르다.** 같은 GPU에서 프레임당 6.5 ms(153 FPS)로 tooltip-detector 11.9 ms
  (84 FPS)·CLAD-Net 10.8 ms(93 FPS)보다 빠르다.
- **이번에는 수렴했고, 과적합이 시작됐다.** 최고점이 cholec80 108 에포크, erop 125 에포크이며
  이후 완만히 하락한다. 150 에포크는 이 설정에서 필요 이상이다.
- **학습 프레임 수를 5배 늘려도 큰 차이가 없었다.** 총 학습 샘플 수를 맞춘 비교에서 정밀도는
  다양성이 높은 쪽이, 재현율은 에포크가 많은 쪽이 근소하게 앞섰다 (§7).

## 1. 실험 설정

| 항목             | 값                                                                           |
| ---------------- | ---------------------------------------------------------------------------- |
| 아키텍처         | YOLOv8s — C2f 백본 + PAN-FPN + 앵커프리 분리형 헤드 (DFL)                    |
| 파라미터         | 11,136,374 (2클래스). `nc=7`로 세면 11,138,309로 참조 체크포인트와 완전 일치 |
| 클래스           | `tool`(어노테이션 bbox), `tip`(팁 좌표 중심 **32 × 32 px** 박스)             |
| 입력             | 640 × 640 letterbox (원본 736 × 480)                                         |
| 라벨 할당        | TaskAlignedAssigner (topk 10, α 0.5, β 6)                                    |
| 손실             | `7.5·CIoU + 0.5·BCE(cls) + 1.5·DFL`, objectness 항 없음                      |
| 에포크           | **150**                                                                      |
| 배치 / lr        | 16 / 0.01 (SGD, momentum 0.937, nesterov)                                    |
| 증강             | mosaic + 좌우 반전 + HSV 지터                                                |
| 추가             | warmup 3 에포크, cosine 감쇠, 가중치 EMA, 그래디언트 클리핑 10               |
| `--frame-stride` | **5** (학습 프레임 5장 중 1장)                                               |
| `--val-frames`   | 1,500                                                                        |
| 사전학습         | 없음 (무작위 초기화)                                                         |

### 데이터

| 데이터셋   | train (stride 5 적용) |                          val |   test | test GT 팁 |         test 세션 |
| ---------- | --------------------: | ---------------------------: | -----: | ---------: | ----------------: |
| `cholec80` |       71,032 → 14,207 | 15,312 (에포크당 1,500 표본) | 98,234 |    161,969 | 40편 (video41–80) |
| `erop`     |      108,424 → 21,685 | 36,140 (에포크당 1,500 표본) | 36,142 |     50,718 |             5세션 |

cholec80은 **영상 단위로 분리된** 스플릿(video01–32 train / 33–40 val / 41–80 test)이다.
erop은 영상 내부를 프레임 단위로 섞어 나눈 스플릿이라 인접 프레임이 train과 test에 함께
들어간다(시간적 누수). **erop 수치는 cholec80보다 낙관적으로 읽어야 한다.**

100–125 에포크를 지나면서 val loss가 다시 오르고 mAP가 완만히 떨어진다. 학습 프레임이
14,207·21,685장뿐이라 그 지점에서 데이터를 다 소진한 것으로 보인다. **이 설정에서는 150 에포크가
필요 이상이며, 100–120 에포크에서 끊어도 같은 결과를 얻는다.** `model.pt`는 최고점에서 저장되므로
보고된 성능은 영향을 받지 않는다.

**2 에포크 만에 대부분이 끝나는 성질은 그대로다.** mAP@0.5가 1 → 2 에포크에서 0.000 → 0.456
(cholec80), 0.699(erop)로 뛴다. 나머지 148 에포크가 더한 것은 0.28·0.20이다.
[CLAD-Net](../../cladnet/docs/experimental-results.md)의 앵커 기반 할당은 같은 시점에 훨씬 낮다.

### 읽는 법

**정밀도에서 앞선다.** 오차 중앙값이 cholec80 3.60 px, erop 2.04 px로 루트 프로젝트의 어느
모델보다 작다. erop에서는 `gaussian-tip` 대비 TP가 9.2 % 많으면서 FP는 3.5 % 적다.

**꼬리에서는 진다.** Hit@50 px가 cholec80 71.8 %로 `gradient-seg`(76.1 %)·`gaussian-tip`(74.7 %)에
못 미치고, P90 오차도 더 크다. 히트맵 모델은 "대충이라도 어딘가는 짚는" 성향이 있고,
탐지기는 "정확히 짚거나 아예 없거나"다. 이 성향 차이가 Hit@10에서는 유리하게, Hit@50에서는
불리하게 나타난다.

**응용에 따라 선택이 갈린다.** 정밀 좌표가 필요하면(로봇 제어, 계측) 이 모델이 낫고,
대략적 방향만 필요하면(카메라 유도) 놓침이 적은 `gradient-seg` 계열이 낫다.

않는다. (분포는 평가 임계값 `conf=0.25`에서 잘려 있다.)

## 6. CLAD-Net과의 비교 — 이번에는 조건이 같다

이전 보고서에서는 두 베이스라인의 격차를 아키텍처 우열로 읽지 말라고 적었다. 팁 박스 크기와
학습 프레임 수가 함께 달랐기 때문이다. **이번 학습에서 그 두 변수가 제거됐다.**

| 조건             | YOLOv8s              | CLAD-Net               |
| ---------------- | -------------------- | ---------------------- |
| 팁 박스          | 32 px                | 32 px                  |
| `--frame-stride` | 5                    | 5                      |
| 에포크           | 150                  | 150                    |
| 입력             | 640 × 640            | 640 × 640              |
| 아키텍처         | 앵커프리 + DFL + TAL | 앵커 기반 + objectness |

| 지표 (cholec80 test)   |     YOLOv8s | CLAD-Net |     차이 |
| ---------------------- | ----------: | -------: | -------: |
| mAP@0.5                |   **0.751** |    0.697 |   +0.053 |
| tool AP@0.5            |   **0.835** |    0.817 |   +0.018 |
| tip AP@0.5             |   **0.666** |    0.577 |   +0.089 |
| Hit@10 px              | **59.87 %** |  56.65 % |  +3.2 pp |
| 팁 오차 중앙값         | **3.60 px** |  4.93 px | −1.33 px |
| Hungarian@10 px 정밀도 |   **0.759** |    0.663 |   +0.096 |
| 프레임당               |  **6.5 ms** |  10.8 ms |    −40 % |

| 지표 (erop test)       |     YOLOv8s | CLAD-Net |     차이 |
| ---------------------- | ----------: | -------: | -------: |
| mAP@0.5                |   **0.858** |    0.788 |   +0.070 |
| tip AP@0.5             |   **0.821** |    0.698 |   +0.123 |
| Hit@10 px              | **75.91 %** |  68.46 % |  +7.5 pp |
| 팁 오차 중앙값         | **2.04 px** |  3.23 px | −1.19 px |
| Hungarian@10 px 정밀도 |   **0.829** |    0.714 |   +0.115 |

**모든 지표에서 YOLOv8s이 앞선다.** 특히 오탐 억제 차이가 크다 — cholec80 Hungarian@10 px
기준 FP가 30,699 대 46,628로 34 % 적다. 팁 클래스에서 격차가 가장 크게 벌어지는데(AP@0.5 +0.09,
+0.12), 작은 물체에서 앵커프리 + DFL + 동적 할당의 이점이 두드러진다는 해석이 자연스럽다.

파라미터는 오히려 이쪽이 많다(11.14 M 대 7.49 M). **CLAD-Net 논문이 주장하는 "더 적은
파라미터로 더 빠르고 정확하다"는 성질은 이 데이터·이 과제에서는 재현되지 않았다.**

## 7. 학습 프레임 다양성 대 에포크 수

이전 학습(30 에포크 × `--frame-stride 1`)과 이번 학습(150 에포크 × `--frame-stride 5`)은
**총 학습 샘플 수가 정확히 같다** (71,032 × 30 = 14,207 × 150 ≈ 2.13 M). 다른 것은 서로 다른
프레임을 몇 장 보았느냐뿐이다.

| 지표 (cholec80 test)  | 30 ep × stride 1 (71,032 프레임) | 150 ep × stride 5 (14,207 프레임) |
| --------------------- | -------------------------------: | --------------------------------: |
| mAP@0.5               |                        **0.772** |                             0.751 |
| tip AP@0.5            |                        **0.697** |                             0.666 |
| 탐지 실패율           |                           9.35 % |                        **8.82 %** |
| Hit@10 px             |                      **60.83 %** |                           59.87 % |
| 팁 오차 중앙값        |                      **3.24 px** |                           3.60 px |
| Hungarian@10 px P / R |            **0.786** / **0.608** |                     0.759 / 0.598 |

| 지표 (erop test) | 30 ep × stride 1 | 150 ep × stride 5 |
| ---------------- | ---------------: | ----------------: |
| mAP@0.5          |        **0.872** |             0.858 |
| 탐지 실패율      |           5.80 % |        **4.79 %** |
| Hit@10 px        |          75.61 % |       **75.91 %** |
| Hit@50 px        |          81.96 % |       **83.16 %** |
| P90 오차         |        100.18 px |      **91.81 px** |

**차이가 작다.** 프레임 다양성이 5배인 쪽이 AP와 정밀도에서 근소하게 앞서고, 에포크가 많은 쪽이
탐지 실패율과 꼬리 지표에서 근소하게 앞선다. 어느 쪽도 결정적이지 않다.

실용적 함의는 분명하다. **`--frame-stride 5`가 같은 결과를 5분의 1 시간에 낸다**
(cholec80 4.1시간 대 이전 3.8시간이지만, 이전은 30 에포크였다 — 에포크당 1.6분 대 7.6분).
영상 프레임의 중복이 그만큼 크다는 뜻이며, 전 프레임 학습은 비용에 걸맞은 이득이 없다.

단, stride 5 쪽에서 **과적합이 나타났다**(§2). 프레임 수를 줄이면 그만큼 일찍 데이터를
소진하므로, stride를 더 키운다면 에포크도 함께 줄여야 한다.

## 8. 속도

세 모델을 **같은 GPU(RTX A6000, cuda:3), 같은 측정 범위**로 쟀다. 전처리부터 후처리까지
프레임 한 장을 처리하는 실제 시간이다.

| 모델                     | 파라미터 |   프레임당 |     FPS | 측정 범위                              |
| ------------------------ | -------: | ---------: | ------: | -------------------------------------- |
| **YOLOv8s**              |  11.14 M | **6.5 ms** | **153** | letterbox + forward + DFL 디코딩 + NMS |
| CLAD-Net                 |   7.49 M |    10.8 ms |      93 | letterbox + forward + 디코딩 + NMS     |
| tooltip-detector `monai` |  11.45 M |    11.9 ms |      84 | 전처리 + forward + sigmoid + 피크 추출 |

**파라미터가 1.5배 많은데도 CLAD-Net보다 1.7배 빠르다.** 이유는 둘로 보인다.

1. **후보 수가 3분의 1이다.** 앵커프리라 셀당 예측이 1개여서 총 8,400개인데, CLAD-Net은
   앵커 3개씩 25,200개다. NMS 비용이 그만큼 줄어든다.
2. **CAM이 비싸다.** CLAD-Net의 CAM은 레벨마다 적응 풀링 4회와 업샘플 4회를 수행하는데,
   P3 레벨에서는 80 × 80 × 336 텐서를 대상으로 한다. 파라미터로는 드러나지 않는 연산이다.

> 이전 보고서가 인용한 tooltip-detector 19.6 ms는 다른 학습이 GPU를 함께 쓰던 중에 측정된
> 오염된 값이었다. 유휴 GPU에서 4회 반복 측정한 결과는 11.78–12.04 ms로 안정적이다.

## 9. 결론과 다음 단계

### 결론

1. **팁 좌표 산출기로 실용적인 수준이다.** 오차 중앙값 2.0–3.6 px, Hit@10 px 59.9–75.9 %로
   루트 프로젝트의 최고 모델과 대등하거나 낫고, 속도는 1.8배다.
2. **동일 조건에서 CLAD-Net보다 전 지표 우위다.** 팁 크기·프레임 샘플링·에포크를 맞춘 비교에서
   mAP@0.5 +0.05~0.07, 팁 오차 중앙값 −1.2~1.3 px, 오탐 34 % 감소, 속도 1.7배다.
3. **`ultralytics` 없이 YOLOv8s를 재현할 수 있음을 확인했다.** 파라미터가 참조 체크포인트와
   모듈 단위로 완전히 일치하고, 스크래치 학습만으로 위 성능에 도달했다.
4. **남은 최대 약점은 다중 도구 프레임의 과소 탐지다.** 큰 오차의 88 %가 여기서 나오고,
   세 접근 모두 같은 문제를 안고 있다.

### 다음 단계 (효과가 클 것으로 보이는 순서)

1. **과소 탐지 대응** — 큰 오차의 88 %를 차지한다. NMS IoU를 낮추거나, TAL의 `topk`를 올려
   GT마다 더 많은 양성을 확보하거나, 팁 클래스에 별도 임계값을 두는 방법을 시험할 수 있다.
2. **에포크를 100–120으로** — §2에서 과적합 시작점을 확인했다. 학습 시간을 3분의 1 줄이면서
   같은 성능을 얻는다.
3. **신뢰도 임계값 조정** — `conf=0.25`는 기본값일 뿐 이 과제에 맞춰 정한 값이 아니다.
   `--conf`를 바꿔가며 평가하면 탐지 실패율과 오탐의 맞교환 곡선을 얻을 수 있다.
4. **팁 박스 크기 재검토** — 32 px은 [CLAD-Net 보고서 §7](../../cladnet/docs/experimental-results.md)의
   논리로 정한 값이고, 이 모델에서 최적인지는 확인하지 않았다. 24 px·48 px와 비교해 볼 수 있다.
5. **입력 캔버스 모양** — 640 × 640 letterbox는 34.8 %가 패딩이다. 800 × 512로 바꾸면 같은
   연산량에서 물체가 23 % 커진다 ([CLAD-Net 보고서 §8](../../cladnet/docs/experimental-results.md)).

## 재현 명령

```bash
# 학습 (완료됨 — data/model/<dataset>/에 산출물이 있다)
./baseline/yolov8sclone/run train-model --dataset cholec80 --frame-stride 5 --val-frames 1500 --device cuda:1
./baseline/yolov8sclone/run train-model --dataset erop     --frame-stride 5 --val-frames 1500 --device cuda:3

# 평가 (완료됨 — data/results/<dataset>/test/에 산출물이 있다)
./baseline/yolov8sclone/run eval-model --dataset cholec80 --split test
./baseline/yolov8sclone/run eval-model --dataset erop     --split test

# 이 보고서가 인용하는 수치 표 재생성
./baseline/yolov8sclone/run generate-summary
```

이전 실험(30 에포크 × `--frame-stride 1`)의 산출물은 `data/model-16x16`·`data/results-16x16`에
남아 있다. §7의 비교표는 거기서 나온 것이며,
`./baseline/yolov8sclone/run generate-summary --suffix "-16x16"`로 그 회차의 수치 표를 다시 만들 수 있다.
